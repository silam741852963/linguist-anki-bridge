# Changelog

## Unreleased

Faster campaigns.

- **Keigo drill cards as text (WP-28)**: a grammar-deck note whose pages are a rephrasing drill (a plain sentence on the front, its business-keigo versions under "Answer" on the back) is reported as `DRILL_CANDIDATE` and can be rewritten in place as a `Linguist Drill v1` note with `plans convert-drill PLAN --template ITEM` and `--request FILE`. The note and its card are kept; the card becomes the drill's one `Production` card. The front shows the plain sentence with the source's reading hints as furigana and a tap-build board: the first polite version cut into bunsetsu chunks plus decoys made from the plain words the drill changes (もらった against ちょうだいした), shuffled with a daily seed, checked against every accepted version as you tap, with Undo. The back lists every accepted version with the polite parts highlighted and its own audio, the change notes and an English translation. The reviewer writes the drill from the pages, so no LLM call is spent; the audio stage voices each answer. `models install japanese_drill --apply` installs the note type; it needs companion 0.7.0, which accepts the drill fields. The binary accepts companions 0.3.0 to 0.7.0.
- **`models install|update japanese_drill`**: the first live run failed with `UNSUPPORTED_PURPOSE: japanese_drill`. The command's purpose argument shared its name with the global `--purpose` option, so it was also resolved as a configuration purpose, and a drill has no configuration preset. The argument is now separate; the other purposes behave as before.
- **Idle sessions wrap up, and an agent session resumes them**: with Codex at its window cap the session driver ran empty ticks for hours instead of wrapping up, because two batches were `ready` for the agent's approval and a ready batch counted as work left to write. Only approved, applying, verifying and merging batches hold the session now. The new `scripts/campaign-session.sh resume-when-ready` waits for the wrap-up and the end of the drafting cooldown, then starts the session again. An agent session runs it in its background, so a campaign resumes on its own only while that session is alive (still no timers). It resumes only a wrapped-up campaign.
- **Generation renders the other items again**: the redraft of grammar batch 274 failed with `RENDERED_DOCUMENT_STALE`. A drafted item went into a new revision with the other items' renders copied unchanged, and those renders were made before the renderer changed (WP-28). The store refuses stale renders, so no plan frozen before a renderer change could be drafted again. Generation now renders every ready item again when it writes a revision, as `regenerate` and `classify` already do.
- **Undrafted batches are drafted again one at a time**: the 30-minute redraft drafted every held grammar batch together (274-279, 10-50 split units each), so all six competed for one Codex window and the agent had to review them all at once. A batch held only by undrafted items is now drafted again only when no lower-numbered `needs_agent` batch still waits for its own redraft. The lowest such batch goes first; the next one starts once it leaves review.
- **A failed `plans generate` no longer reads as "nothing new"**: grammar batches 274-279 stayed held after the redraft fix. The review step treated a `plans generate` that failed as a whole command (no JSON, an error that is not an outage) like a run that drafted nothing, so the batch went back to waiting and spent its one redraft for that revision. Such a failure is now a step failure with its error recorded (`GENERATION_BASE_CONFLICT`, a plan changed by an agent decision meanwhile, reviews again instead). A batch held only by undrafted items is now reviewed again at most every 30 minutes, not once per revision, so a redraft lost to an outage is tried again.
- **Sessions resume any pause**: `scripts/campaign-session.sh start` refused a campaign paused for anything but a wrap-up or a Codex limit ("look at it, then run: campaign resume"); it now resumes it, since the operator starts again after fixing the cause. The `campaign-tick` skill lets the agent fix a pause's cause (defer, `campaign reopen`, `campaign requeue`) and resume; it still never closes, cancels, rolls back or restores. `scripts/campaign-agent.sh` no longer denies `campaign resume` or `campaign requeue`.
- **`campaign resume` without `--by-user`**: resuming a paused campaign needed a terminal or `--by-user` (`CAMPAIGN_RESUME_BY_USER_REQUIRED`), so an agent driving a session for the user could not resume one after fixing the cause; the user had to type the command. Resume now works from any caller. `--by-user` is still accepted and does nothing; `scripts/campaign-session.sh` no longer passes it. The unattended agent wrapper still never resumes, and `campaign tune --agent-share-max` keeps its `--by-user` guard.
- **`campaign reopen` on an apply that wrote nothing**: batch 280 paused the campaign with `SPLIT_PREFLIGHT_FAILED: … APPLY_TARGET_DECK_UNCONFIGURED`. A `plans generate --use-current-settings` run by hand without the campaign source's `--set` flags had frozen a revision without `purposes.japanese_grammar.target_deck`, and that revision was approved. Its first split group failed before writing anything, but the batch was `applying`, and `campaign reopen` accepted only an `approved` batch, so the only way on was to cancel. Reopen now also takes an `applying` batch with no apply job, no follow-up intent, no split group done and no note committed, and clears its step failures.
- **Campaign batches stuck on undrafted units**: grammar batches 274–280 of the live campaign sat in `needs_agent` for a day with only `PLAN_NOT_READY`, although every note was settled. Their split units still had empty meanings (`REQUIRED_CONTENT`): the review rounds had run out before generation drafted every unit, and a `needs_agent` batch is reviewed again only on a newer plan revision or a met need, so nothing drafted them and no agent decision could. Such a batch, held only by `PLAN_NOT_READY` with an active item's required content empty, is now reviewed once more per revision, which drafts the missing units; once per revision, so a draft that never comes cannot loop.
- **`campaign item --settled` retries failed drafts**: a note whose drafts failed (`GENERATION_FAILED`, for example after repeated `AGENT_TIMEOUT`) stayed failed after the agent settled it, so the batch could never become ready; the only ways out were a defer or `campaign reopen --fresh`. Settling a note now clears its draft failures, so the next tick drafts it again. The `GENERATION_FAILED` hint names all three choices.
- **Part-of-speech tags from a label table (WP-27)**: every dictionary label now goes through `resources/taxonomy/labels-v1.tsv`, which gives it one role (part of speech, register, region, field, script, origin, note or name). Only part-of-speech labels make `lab::pos::<class>` tags, from ten classes grouped from Universal Dependencies (noun, verb, adjective, adverb, pronoun, function, number, expression, affix, interjection), with subclasses such as `lab::pos::verb::godan-ru`. Labels such as `Wikipedia definition` or `Computing` were tagged `lab::pos::wikipedia-definition` and `lab::pos::computing`; they now become `lab::field::computing` or no tag. The other facts get their own tags: `lab::pos-also::<class>` (the word's other uses, such as `issue` as a verb), `lab::register::*`, `lab::region::*`, `lab::field::*`, `lab::script::kana`, `lab::origin::wasei` or `gairaigo`, and `lab::note::*`. A Jisho sense with no labels takes those of the sense before it; a word whose sense has none takes another entry of the same form; a card with no class is tagged `lab::pos::unknown`. A grammar card takes the class of the slot its pattern attaches to (`V て ください` is a verb, `N1 は N2 です` a noun, `S1 が、S2` a function word) and `lab::form::<form>` for the form it requires (`te`, `nai`, `masu`). Apply owns the `lab::` namespace: it drops a `lab::` tag the renderer no longer derives and keeps the user's own tags.
- **Part-of-speech colours (WP-27)**: the vocabulary and grammar cards take their accent colour from the `lab::pos::<class>` tag (the templates put `data-tags="{{Tags}}"` on the card root): one colour per class, with a light and a dark tone, tested for WCAG AA contrast against the panel in both modes and for colour-vision deficiencies on noun/verb, noun/adjective and verb/adverb. In the Meaning panel each sense and part-of-speech chip carries its class colour, and a sense of another class than the card's (`issue` as a verb on a noun card) gets a border in its own colour. Existing note types are updated with `models update`.
- **`models update PURPOSE [--apply]` (WP-27)**: rewrites the templates and CSS of a managed note type in place, with the same fields and template names, so no full sync is needed. Only a note type at a known earlier manifest of that model is updated (`MODEL_UPDATE_UNKNOWN_PRIOR` otherwise: a note type edited outside the bridge is never overwritten). It runs under a collection checkpoint and a journal, and a lost response is settled by `recover reconcile`. The preview says `current`, `update`, `unknown_prior` or `absent`. Writes need companion 0.6.0, which adds the `update_model` variant; companions 0.5.0 and 0.6.0 are both accepted.
- **`notes retag [NOTE_ID...] [--all] [--apply]` (WP-27)**: re-renders applied notes from their stored documents with the current renderer (part-of-speech colours in the Meaning HTML, the label-table tags, the domain profile) and writes the fields and tags in place, with no LLM call. A note that changed since its latest apply is skipped (`RETAG_NOTE_EDITED`) and never written. The preview lists each change (`--fields` shows each field before and after); `--apply` takes one collection checkpoint and writes each note as a journaled apply operation with an exact `restore_note`, a snapshot and a read-back, so `recover reconcile` and `snapshots restore` work on it. Cards, scheduling, decks and the note type stay.
- **Domains in the enrichment call (WP-27)**: the vocabulary and grammar drafts also choose the card's domain from `domains-v1` (`resources/taxonomy/domains-v1.json`: 459 three-level leaf paths from Threshold 1990 and ISCED-F 2013, and Threshold's communicative functions for grammar), at no extra call. The note stores it as `profile` (`domain`, up to two `secondary` paths, grammar `functions`, and the taxonomy version), validated against the list (`PROFILE_INVALID`) and tagged `lab::domain::<l1>::<l2>::<l3>`, `lab::domain2::*` and `lab::function::*`. The dictionary's field labels and the Cambridge topic are sent as hints. A reply whose domain is not in the list loses the profile, not the draft; a note whose only missing field is the domain is not drafted for it.
- **More of the card profile (WP-27)**: grammar drafts also judge the register (`lab::register::*`), vocabulary drafts the connotation (`lab::connotation::*`) and a Japanese verb's transitivity partner (開く for 開ける, kept only when it shares the kanji stem and its ending is a known pair in the other direction; shown under "Transitivity pair"). Derived without an LLM: `lab::attach::*` (what a grammar pattern attaches to), `lab::cefr::*` (Cambridge now gives each sense its CEFR level), `lab::origin::kango|wago|mixed` (from the readings of each kanji) and a negative connotation for derogatory labels. A vocabulary profile that leaves the dictionary's field label shows `DOMAIN_HINT_IGNORED` in review.
- **Coloured grammar slots (WP-27)**: in a grammar card's formation, `V`, `N` and `い-Adj` take the colour of their class (`V` red, `N` blue). Existing grammar note types are updated with `models update japanese_grammar --apply`.
- **`notes retag` on the real companion**: the first live run wrote nothing. Two checks blocked it: the store re-checked each note's old approval against today's validation (`APPROVAL_CORRUPT`) before recording the operation, and the companion refused the `restore_note` under a plan approval (`BRIDGE_OPERATION_BODY_INVALID`). A retag now reads the approval as recorded (its record digest still checked; apply still re-checks before a new write). It runs under a retag decision of the restore kind that binds that plan approval to the note, its observed state and the exact payload, and the apply receipt accepts that kind.
- **`notes retag` over a long run**: a full-collection run (4,159 notes, about 5 minutes of reads) twice ended with `ANKI_DEPENDENCY_UNAVAILABLE` when one AnkiConnect read dropped its connection. The preview's reads are retried up to 4 times with a growing wait before the run stops. A note whose creating apply was restored, and so deleted, is now reported as `RETAG_NOTE_MISSING` instead of `RETAG_NOT_APPLIED: … is restored`. The writer lease is renewed before each note: the first full run stopped after 72 notes with `LEASE_STALE_OR_EXPIRED`. Every read-only AnkiConnect request (including the companion's `labInspect` and `labOperationStatus`) is now resent up to 3 times when its connection drops; owner, mutation and rebind requests never are. A run had stopped after 555 writes on one dropped read-back, leaving an operation for `recover reconcile`.
- **Faster writes on a large collection (companion 0.6.1)**: a full `notes retag` wrote one note every 8.7 s. Two checks grew with the collection's history. The companion validated every operation in its ledger, parsing each payload, twice per write (`labBegin` and `labMutate`): 2.2 s each at 15,000 operations. It now validates a closed history once per Anki session and again only when its event count or the ledger schema changes; dropping an immutability trigger to forge a row changes the schema, so a forged history still fails closed (0.02 s per scan after the first). The bridge re-hashed the multi-gigabyte collection checkpoint before every note; it now hashes it once per process and re-hashes when the file's inode, size, modification or change time differ. The binary accepts companions 0.5.0 to 0.6.1.
- **Fewer round trips per write**: after the ledger and checkpoint fixes a retag still took 1.6 s per note, nearly all of it waiting on AnkiConnect. The bridge no longer asks for the active profile before and after each session-bound companion call (`labBegin`, `labInspect`, `labMutate`, `labOperationStatus`): the companion re-observes the profile on those calls and a profile switch ends the session (`BRIDGE_SESSION_CONFLICT`); `labCapabilities` still pins the profile, and `labEnd` and `labRebind` keep the check. An operation's status is first read after 10 ms and the wait doubles up to `anki.commit_interval_seconds`, instead of a fixed 0.25 s. A retag snapshot no longer archives the note's media, and a note whose current render would reference other media files is skipped (`RETAG_MEDIA_CHANGED`) rather than written. Connections to AnkiConnect are no longer pooled: AnkiConnect closes each connection after its response without saying so, and reusing one as it closed was the dropped request that stopped three long runs.
- **`plans classify PLAN` (WP-27)**: gives notes drafted before the domain question a judged profile, in batches of 25 notes per agent call, as a new revision that differs only in profiles; after review and approval, `notes retag` writes the profile's tags to the applied notes under that approval.
- **`plans classify` keeps the review decisions**: the first live run published a revision that could not be approved. It cleared every review decision, left the document review records bound to the digest before the profile, and so rendered nothing (render needs a ready document); replaying the campaign policy instead rewrote the documents, so `notes retag` rightly ignored that revision. Classify now moves each decision and review record of a classified document (bound to its base digest or its digest without a profile) to its new digest, keeps the decisions of documents left alone, and renders after that; `notes retag` compares documents without the digest a review is bound to.
- **Word harvester `harvest` (WP-25)**: finds words met in the deck's own example sentences that the deck has no card for. `harvest scan --purpose japanese_vocab|english_vocab` reads the deck read-only from Anki and each note's applied document from the store (examples, collocations, usage and nuance; a note never revamped gives its example fields), and keeps candidates in the store (schema 16) with every sentence they were met in. Japanese uses Lindera with the embedded IPADIC dictionary (offline): particles, auxiliaries, numbers, names and single kana are dropped, conjugated words become their dictionary form, and adjacent nouns stay whole when the deck or a local JMdict file (`harvest.jmdict_path`, optional) knows the compound. English uses a stop list and a rule lemmatizer with an irregular table, extended by the irregular forms Cambridge pages list (now stored as entry metadata). `harvest list` ranks by i+1 sentences (the word is the only unknown one), then the number of notes, frequency and attested provenance; `show`, `ignore`, `known`, `unignore` and `queue` (or `queue --top N`) keep the user's choices across rescans; `harvest export` writes the queued words as v2 vocabulary JSONL for `vocab add --format jsonl`, with the best sentence as the first example. A rescan reads only notes whose document changed; `--full` reads all. No harvest command writes Anki. A kana word meets its kanji deck note by reading (できる and 出来る), and grammar words (ない, かもしれない), symbols and English explanation text are left out. A plural or honorific suffix never joins its noun (子どもたち is 子ども even though JMdict lists it), and a JMdict word marked common with no `nfXX` band (店, まだ: `ichi1` only) ranks at band 24 instead of after every banded word.
- **`doctor --labels` (WP-27)**: lists the dictionary labels in the store that the label table does not know, without contacting Anki.
- **Independent lanes**: `campaign run` runs the write lane and `prepare_parallel` prep workers (1-8), each looping on its own; prep workers claim distinct batches and read each batch fresh before a step. A lane that panics stops the tick.
- **`campaign tune`**: change `prepare_ahead`, `prepare_parallel` and `agent_runs_per_day` of a running campaign (a `tuned` event; guardrails stay frozen). `campaign status` shows the effective `limits`.
- **Agent on its own timer**: `scripts/campaign-agent.sh` and `campaign install-timer --agent-script` (every 5 minutes). `campaign agent-slot` .. `campaign agent-done` hold `needs_agent` batches so a review never races the agent's edits; `campaign status` shows `agent_active`.
- **Quality fixes from the agent's spot checks**: the policy picks a sense only by an equal reading (台所 だいどころ no longer takes だいどこ; `に じゅう なな; に じゅう しち` reads as two readings, not syllables; readings on separate lines too); a draft whose examples repeat its collocations or the bare word (白菜) is refused (`GENERATION_EXAMPLE_NOT_SENTENCE`); a collocation that only holds the word's kanji inside a compound (体温 for 体 read からだ) and a nuance contrast with another spelling of the word (朝ご飯/朝御飯) are rejected; a draft whose explanations are not in the explanation language is refused (`GENERATION_EXPLANATION_LANGUAGE`); the vocabulary prompt states these rules.
- **Generated dictionary entries in prepare jobs**: the job passed an empty environment to the entry's provider, so an agent (Codex) could not be found (exit 127) and every phrase without a dictionary entry was left without a meaning; it now gets the job's environment (`dictionary` regeneration too).
- **Preparation**: `jobs publish --skip-failed` gives the plan a selection receipt naming exactly the captured notes (it was refused with `PLAN_SELECTION_INVALID`, and the campaign retried it without end); the campaign reads notes again that failed because Anki was busy or unreachable (after 5 minutes, up to 3 times) before leaving any out, and a refused publish counts as a step failure; a job whose attempt budget is spent is published without those notes at once; a step that moves a batch resets its failure count.
- **Generation**: a draft keeps the item's decisions about the source alone (a source image's role, verified source or OCR text), rebound to the new document, so an agent's image decision no longer reopens after the next draft; a new draft drops the engine markers of the item's earlier drafts (a stale `GENERATION_ENGINE_UNVERIFIED` from a local fallback no longer blocks the item); `plans generate --all-items --pending` drafts an item at most 3 times (`GENERATION_ATTEMPTS_EXHAUSTED`).
- **`llm.agents.codex.reasoning_effort`** (default, minimal, low, medium, high, xhigh): passed to Codex as `-c model_reasoning_effort`; `default` keeps the Codex configuration's own. An example sentence on a Japanese, Chinese or Korean card must contain that script (`GENERATION_EXAMPLE_LANGUAGE`; a draft gave `x = x`).
- **Agent timeouts end the whole agent**: an agent runs in its own process group and a timeout kills the group, so a wrapper's child (`codex-meter.sh` -> `codex exec`) no longer outlives its deadline.
- **More spot-check findings in code**: a nuance contrast with one of the word's own forms (節約 and 節約する) is rejected; a draft that copies the prompt's placeholder ("the accepted expression", or "the expression" on a vocabulary card) is refused (`GENERATION_PROMPT_WORDING`); the vocabulary prompt asks for the word by name.
- **A batch whose drafts failed is never ready**: `plans generate` errors (a usage limit, a provider down, a draft the checks refused) were read as "nothing new to draft", so a batch could reach `ready` without examples, collocations or nuance. A usage limit now waits; any other failure drafts the note again, up to 3 times, then leaves it to the agent (`GENERATION_FAILED`).
- **Source decisions survive a draft and a sense choice**: the draft path cleared every review after the merge had kept the item's decisions about the source alone, and a sense choice (which the policy makes again after every draft) cleared them too, so an agent's image role and classification went back to the agent after each draft; both now keep the source-only decisions, rebound to the new document while they still settle their issue.
- **`campaign reopen --fresh`**: a ready, needs_agent or approved batch without an apply job is prepared again from scratch with the current settings.
- **`campaign requeue`**: notes that finished batches deferred (default reasons `AGENT:`, `APPLY_FAILED:`) go round again in new batches.
- **Fallback through a usage limit**: `llm.quota_cooldown_seconds` (default 1800): an agent or API that reports its usage limit is skipped for that long (`AGENT_QUOTA_COOLDOWN`, a marker under `storage.state_dir/agents/` shared by every process), so the next provider of `llm.fallback` (for example local Ollama) drafts at once; then it is tried again. Drafts go one at a time while that leaves Ollama first. A campaign waits for the quota only when every provider of the chain hit its usage limit; a fallback that failed otherwise counts as a failed draft.
- **A thin draft goes to the next provider**: a vocabulary draft asked for examples that adds fewer than two (or than it was asked for) fails with `GENERATION_FEW_EXAMPLES`, and the chain tries its next provider (local drafts of 代替, 再帰 and 相乗 had one example each).
- **Candidates under one reading need no reading match**: when a note's reading field is filled but holds no kana reading (一人っ子 with `一人っ こ`) and every candidate sense has one reading, the policy chooses as among equal readings (screenshot, then dictionary order); it went to the agent with `SENSE_READING_UNMATCHED`. A note with a kana reading that matches no candidate (台所 だいどこ) or with no reading still goes to the agent.
- **An example in the entry's kanji spelling uses the word**: the policy counts the written forms of the dictionary entry holding the selected sense as forms of the word, so a note written in kana (ほうとう) keeps examples written 宝刀; they were all rejected and the note ended with no example.
- **Fewer wasted drafts**: (1) a drafted item whose only empty fields are nuance, collocations or grammar forms is not drafted again (`GENERATION_NOTHING_TO_FILL`): an empty list is a valid answer, and 20 of 25 notes of a batch were drafted three times for an empty nuance; (2) a full vocabulary draft whose only fault is its examples (`GENERATION_EXAMPLE_LANGUAGE`, `GENERATION_INCOMPLETE_EXAMPLE`, `GENERATION_EXAMPLE_NOT_SENTENCE`, `GENERATION_SCRIPT_MIXED`) keeps its other fields and the next round asks for the examples alone. Codex wrote `{"sentence": "translation"}` in about a third of full drafts and in none of six examples-only requests.
- **`llm.agents.codex.max_window_percent`**: drafting uses at most this share of Codex's own five-hour window. Codex runs keep their session (`--json`, not `--ephemeral`) so the rate limit Codex reports is read from the session file, which is then removed; at the limit Codex cools down until the window resets. `campaign status` shows `agent_cooldowns` and `drafting_available`, and `scripts/campaign-session.sh` wraps the session up by itself once no provider can draft.
- **A batch whose every note was deferred is finished by its approval**: `campaign approve` moves it to `done` (nothing to write) instead of refusing with `CAMPAIGN_NOTHING_TO_APPROVE`, so `campaign requeue` sends its notes round again.
- **A review without the companion's collection session waits**: while Anki closes and reopens its collection (a checkpoint export), `plans resolve-batch` gets `CAPABILITY_UNAVAILABLE`; the campaign waits instead of counting a step failure (three paused it).
- **Refused drafts are kept**: a draft the validation refuses is appended, with its error, to `<storage.state_dir>/agents/rejected-<provider>.jsonl` (moved to `.old` past 8 MB), so a repeated `GENERATION_*` failure can be read.
- **A kana word is its own reading**: the policy matches the sense of a note written in kana alone with no reading or pronunciation (こらえる, やがて) by the word itself; such notes went to the agent with `SENSE_READING_UNMATCHED`.
- **する verb forms find their stem's entry**: a note written メモします, 勉強した or 掃除する with no entry of its own takes the entry of its stem when that entry is labelled a する verb (sense review, templates, rendered meaning, the policy's reading match); it was left with no meaning.
- **Spelling variants find their dictionary entry**: a note written ジャガ芋 takes Jisho's じゃが芋 entry (spellings that differ only in katakana against hiragana are one word) for the sense review, its templates, the rendered meaning and the reading; it was left with no meaning.
- **A collocation gloss copied from an example translation, or shared by two different phrases, is refused** (`GENERATION_COLLOCATION_GLOSS`; 整う got full sentences as glosses, 血脈が通う and 血脈を流れる both "blood vessel"); a する-verb phrase that goes on to a noun (リセットする機械, "a machine that resets") glossed as the verb with that noun as its object ("to reset a machine") is refused too, and so is a phrase ending in kanji or katakana (a noun phrase: 計算ミス) glossed as a verb ("to make a mistake in calculation"); a longer phrase glossed with the word's own meaning (インスタントラーメンを食べる: "instant ramen") too.
- **Examples use the word; affixes keep theirs**: an example with no form of the word (直ちに drew a sentence with たちまち) is rejected; the compound rules skip prefixes, suffixes and counters (副, 総, 代), which are only ever written inside compounds and had every example rejected.
- **Source decisions survive every content change**: an image's role and verified source or OCR text are rebound after any decision that changes the document (a rejected generated fact, a chosen media candidate), not only after a sense choice; the policy rejecting a collocation had sent an agent's image role back to the agent.
- **The sense the learner's screenshot names**: among dictionary senses of the note's reading, the policy chooses the one whose definitions share the most words with the OCR text of the note's own images (a kept dictionary screenshot), when one shares strictly more; otherwise dictionary order as before (得意 took "pride" where the screenshot said "one's strong point").
- **Capture failures say why, and transient ones retry**: a catch-all capture failure keeps the error it classifies (`error_detail` in `jobs items`, `jobs publish --skip-failed` and the campaign's `PREPARE_FAILED` deferral); one from a dependency that was away a moment (timeout, unavailable, busy or locked, rate or usage limit, HTTP 5xx) is retryable `SOURCE_CAPTURE_TRANSIENT` instead of a permanent `SOURCE_CAPTURE_REVIEW_REQUIRED` (28 campaign notes had failed for good and captured cleanly when run again).
- **`campaign tune --agent-share-max X --by-user`**: the agent share guardrail (0.05-0.5) moves only as the user's step (a terminal or `--by-user`); image-heavy batches tripped the 20% default with dictionary screenshots the agent archived.
- **A batch never waits on needs already met**: a batch waiting for the agent is reviewed again when every need it lists is a review issue the plan no longer holds open (a review that raced the agent's decisions recorded needs already met).
- **No stale agent needs**: a review stamps the revision its undecided list describes (the policy pass's own), not a later read; an agent decision that landed while the review ran makes a newer revision, so the batch is reviewed again instead of waiting for the agent on needs already met (the `--settled` workaround is no longer needed).
- **An unresolved reconcile is tried again**: `recover reconcile --apply` exit 4 (it ran, the outcome is still unresolved, for example Anki away a moment longer) is a step failure retried by the next step instead of an immediate `CAMPAIGN_PAUSED_UNKNOWN_OUTCOME`, and its outcome (stdout) is named instead of an empty detail.
- **Compounds are not the word**: a noun written with trailing kana is part of a compound when a kanji or katakana noun follows it (物干し台, 物干しロープ for 物干し), and an example whose kanji word appears only inside compounds (球体, 球場 for 球) is rejected.
- **Hangul on a Japanese card is refused** (`GENERATION_SCRIPT_MIXED`; 決して drew 絶대로 for 絶対に) and the note is drafted again.
- **A collocation that is one of the word's own forms is rejected** (遠慮する for 遠慮), as a nuance contrast already was.
- **Agent call budget**: `llm.agents.max_calls_per_window` (0 = none) and `llm.agents.budget_window_seconds` (default 18000): an agent or API that started that many calls in the window is skipped like one at its usage limit until the window frees (a call log under `storage.state_dir/agents/`), so `llm.fallback` drafts meanwhile and a quota shared with other work is never run out.
- **Campaigns never draft with an uncertified local engine**: `plans generate --pending --certified-engine-only` (the campaign passes it) leaves out a local Ollama engine that no passed certification covers (identity and version; an upgraded Ollama loses it), and refuses each item with `GENERATION_ENGINE_UNVERIFIED` when that engine is the provider drafts go to now. The campaign pauses with that code instead of writing drafts that approval would refuse; `scripts/campaign-session.sh` certifies again and resumes when the certification passes.
- **`campaign wrap-up`**: ends a session cleanly: pauses the campaign (a campaign already paused keeps its reason), lets the running tick finish its step, ends agent processes left by a generation process that is gone, closes an open agent turn and records a `wrapped_up` handoff event (exit 5 while a tick still runs). `scripts/campaign-session.sh start|watch|status|wrap-up` runs a campaign from a session: it starts VOICEVOX when needed (never Anki), resumes a wrapped-up campaign, drives ticks back to back, and on wrap-up stops its driver, watchers and what it started.
- **Parallel generation**: `llm.agents.parallel` (1-8, default 1) drafts that many items at once from an external provider in `plans generate --all-items --pending`; local Ollama stays one at a time.
- **A bracketed frame is a collocation, the word is its head**: 費用(がかかる) was looked up whole, so Jisho found nothing and the generated entry described the frame (ひようがかかる, "to cost money"). The head word (the text outside brackets that hold Japanese, without kana spacing) is now the lookup term, the generated entry's word and the dictionary form, and the prompt makes the written-out frame (費用がかかる) the first collocation. A slash inside brackets separates a frame's alternatives, so 体重(が増える／を減らす) is no split candidate. English brackets stay part of the phrase (`be (all) the rage`).
- **Piper as the dictionary's synthesis fallback**: `audio.synthesis_fallback=piper` with `audio.provider=dictionary` failed with `SPEECH_PROVIDER_UNAVAILABLE` (the preflight accepted only `audio.provider=piper`); an English phrase without a Cambridge recording now gets Piper audio. `doctor` checks Piper when it is the fallback.
- **A one-unit grammar split rewrites a single-pattern page**: OCR text verbatim is no pattern, and a plan edit cannot set the typed pattern; a one-unit split publishes the reviewer's authored unit on the item in place, without a group.
- **A grammar note's history goes to its Recognition card**: the vocabulary task map named a task Grammar v4 does not have, so the first grammar batch failed with `SOURCE_TASK_MAP_INVALID` and paused the campaign.
- **Dictionary screenshots are recognized more often**: a dictionary capture is archived whatever its layout score (dark Jisho, Kotobank and Mazii captures with one or two short lines were kept as pictures: 39 of 830); OCR dictionary markers now include part-of-speech lines, numbered senses, Kotobank headings, Mazii links, Jisho badges, Cambridge grammar codes (`[C]`, `B2 [S]`), headword lines (`trap noun (MUSIC)`), pronunciation lines (`us /ˈswɪft/ uk /swɪft/`), a part-of-speech label followed by the UK/US audio buttons, and their usual OCR misreads (`nouni[C]`, `use` for `us`). An English card's capture of a Cambridge picture (with its Getty credit) is archived and the dictionary's own picture takes its place.
- **Cambridge register labels inside a definition become labels**: "infml" and "disapproving" ran into the definition's first word ("infmldisapproving a long excuse").
- **Anki closing its collection is waited out**: a capture read that AnkiConnect refuses while the collection is closed (a checkpoint export) is retried (five whole batches were left out), and an apply halted by a lost collection session (`CAPABILITY_UNAVAILABLE`, `ANKI_DEPENDENCY_UNAVAILABLE`) resumes on a later tick instead of pausing the campaign.
- **Provider outages are made good**: a note prepared while Codex was at its usage limit gets its generated dictionary entry written again by the review step (waiting while still limited, three tries for other outages); a wrong Godan label on a phrase is dropped instead of refusing the whole entry; an item whose audio synthesis found the service unavailable is enriched again (up to three times) before it goes to the agent. Deferred notes are left out of these reruns.
- **Batch bookkeeping**: the review step ends on a policy pass and judges readiness from the final plan; a batch whose plan exceeds the size limits is halved, also when a `--skip-failed` publish is over the limit; `campaign requeue` also takes the deferred notes of a batch skipped because none prepared (60 notes of five batches); reconcile retries with `--rebind` only after `SESSION_CHANGED`.
- **More generation checks**: a collocation list with a phrase that does not contain the word (or its reading or stem), a repeated phrase, or the word itself is rejected; a vocabulary draft naming "the expression" (54 ready notes said "less honorific than the expression") is refused; the prompt says examples are sentences, never the field names (`{"sentence": "translation"}` in 6 of about 100 drafts).
- **Session scripts**: the session driver wraps up only when no batch is ready, approved, applying, verifying or merging (it paused batch 110 mid-apply) and logs each line once; `campaign-tick.sh` passes the agent the absolute CLI path; `scripts/codex-meter.sh` logs each Codex generation call (tokens, duration, exit).
- **Cambridge idioms and phrasal verbs are found**: pages for `be pressed for time`, `on ice` (idioms) and `go back on something` (phrasal verbs) parsed to no entry, because their headword has no `.hw` and an idiom sits in `.idiom-block`; they are read like word pages, and a phrasal verb's header recording (its verb alone, `go`) is not taken as the phrase's. Lookups go through Cambridge's search, which lands a phrase on the entry that holds it (`palm something off` on `palm off`, `be (all) the rage` on `be all the rage`); the entry's source is the page's canonical link. An English word with no entry at all (`have the time of your life`) gets a generated entry in Cambridge's style (`dictionary.generate_missing`).
- **A non-breaking space in a field is a space**: Anki's editor writes `&nbsp;`, so `go back on something` never matched its dictionary headword.
- **A slash separates words**: `plans split-vocab` refused `とにかく/ともかく` (an ASCII slash) as one word; a slash inside brackets still separates a frame's alternatives.
- **Wiktionary examples stay with their sense**: the definition response repeats a sense's examples under the sense before it (`put him on ice`, meaning kill, under "on hold"); an example listed under several senses stays under the last one only. Definitions lose the space an empty usage label leaves.
- **Image decisions survive a regenerate**: `plans regenerate --stage dictionary|enrichment` cleared every decision, so the agent's image roles and classifications went back to it; decisions about the source alone are rebound to the regenerated item while they still settle their issue.
- **Spellings of one word are one note**: a Japanese note listing several spellings of one word (`お勧め お奨め おすすめ オススメ`) was a split candidate, and a split would make four near-identical notes. When one dictionary entry lists every unit as a form or reading, the dictionary stage keeps one note: the first unit is the word, the others its spellings (new `spellings` field, shown under "Also written" with the entry's own forms; `VOCAB_SPELLINGS_MERGED`). Separate words (祖父, お祖父さん) still split.

## 0.3.0 — 2026-10-11
