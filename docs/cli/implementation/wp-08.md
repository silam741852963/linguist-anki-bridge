## Completion audit — 2026-10-03

- Screenshot groups: revamp OCR runs over the item's source images in reading order before publication. For grammar items, every OCR line that starts with a pattern marker (`〜`, `～`, `~`) — or every line when none does — becomes a candidate in one `GRAMMAR_SEGMENTATION_REVIEW`. The candidates are kept verbatim, including negations and operators such as `/`.
- Reviewed segmentation: `ReviewChoice::Segmentation` takes candidates in reading order. One region confirms a single unit and fills an empty pattern verbatim. Several regions record a split decision and raise `GRAMMAR_SPLIT_PENDING` until `plans split-grammar` publishes the units. `plans split-grammar PLAN --template ITEM` prints an editable request with the chosen patterns. Generation is refused while segmentation or a split is pending.
- Anchor and children: the split keeps exactly one reviewed anchor (the existing document identity). Siblings are fresh notes: captured card state and task maps are removed, tasks are Recognition plus Application when originally requested, and the source archive stays linked. Segmentation issues end with the split.
- Authored path: grammar add works under the default `dictionary.provider=auto`, because grammar has no dictionary stage; an explicit dictionary provider for grammar is rejected. Use key, formation and examples stay separately attributed.
- Focused prompts: Recognition templates ask what the pattern expresses (English, Vietnamese and Japanese explanation templates) and are leak-checked against the meaning; a recognition prompt that contains the meaning is now an `ANSWER_LEAK`. Application templates blank the single literal occurrence of the pattern in an example and give an answer naming the completion and its meaning. Answers listing acknowledged alternatives are accepted.
- Conflicting claims: differing Source/User evidence claims for pattern, meaning, formation, usage or reading raise `SOURCE_CLAIM_CONFLICT`, which is resolved only by a content verification that names every conflicting evidence ID.

Tests: `tests/grammar.rs` covers a Japanese screenshot with Vietnamese explanation and five patterns, including negation/operator fidelity, ordered segmentation, the pending split, the template, the split and sibling card-state isolation. It also covers single-unit pattern fill and pattern keep, low-confidence/failed/empty OCR, English and Vietnamese recognition/exercise suggestions, discontinuous and repeated patterns, recognition leaks, acknowledged multiple answers, typed exercise/recognition resolution, conflicting source claims, and grammar add under `auto` versus explicit dictionary providers. A CLI test covers `split-grammar --template` argument and decision requirements. Existing tests cover the authored split, anchor rules and limits.

Evidence: `cargo test --locked --workspace --quiet`, `cargo clippy --locked --workspace --all-targets -- -D warnings`, `cargo fmt --all -- --check`, `python3 docs/cli/validate.py` and `git diff --check`.

## Known limits — revisit after all packages

- Segmentation is line-based: one OCR line is one candidate. Patterns that wrap onto several lines, tables and multi-column pages are not reconstructed. Formation, explanation and examples are not extracted from OCR text into units; split units start with empty use key, meaning and formation, which must be authored, or generated after the split (generated facts then need review).
- OCR mistakes in pattern text are carried verbatim; only reviewer inspection catches them.
- Live revamp captures do not contain native card state yet (WP-03). Sibling isolation is proven with injected card state; the anchor's real scheduling history has not been preserved through a live split.
- Siblings get Recognition plus Application only when originally requested; there is no per-unit task choice. Native split execution (child-first writes, journals, recovery) belongs to WP-11/WP-12.
- Exercise suggestions need one literal occurrence of the pattern in the first matching example. Discontinuous or inflected patterns get none, and alternative answers must be authored. Ambiguous prompts that have several unacknowledged valid answers are not detected automatically.
- Recognition templates exist only for English, Vietnamese and Japanese explanation languages; Vietnamese text quality is unreviewed by a native speaker.
- `SOURCE_CLAIM_CONFLICT` compares whitespace-normalized text only; it has no semantic equivalence check and does not compare OCR evidence with field values.
- There is no grammar dictionary or grammar audio adapter, and `plans regenerate` remains unavailable. Grammar generation with a non-English explanation language depends on the model and is unverified.
