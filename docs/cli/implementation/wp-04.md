Steps: implement RFC 8785 lab-jcs-v1 and SQLite WAL/synchronous FULL/private fsync asset publication; implement schema versions, atomic revision storage, private asset archive, referential integrity, checksums, fsync discipline, leases/liveness, journal step intents and read indexes; make immutable snapshot original distinct from actual after-state. ## Storage evidence (2026-10-03)

The root `linguist-store` now uses schema 8. The new snapshot tables retain immutable original bodies and asset references separately from one native after-state receipt and actual after-state asset. Publication verifies every archived asset and media size before committing a snapshot. Reads verify body hashes, the reference index and archived bytes. A structural native receipt with a read-back and archived evidence can be attached once only when its step ID, payload, approval, lineage, session and observed digest match the linked started journal step. The actual after-state bytes must already be archived under that observed digest. This local record does not finalize a journal or authorize a native write. Schema 7 upgrades create a checked private SQLite backup before adding the tables.

`snapshots list` and `snapshots show` now read this evidence without creating state. List pages by UUID and supports exact source note, journal job and recorded/unknown post-state filters; a cursor advances by scanned records even when the filter excludes them. Restore/export remain later-package work. Store tests exercise restart, a process killed between publishing asset bytes and metadata, file-size-limit write failure, transactional index failure, missing/corrupt assets, immutable history and schema-7 backup. Existing store tests cover journal unknown-state restart and no unverified finalization, lease contention/reclaim and future-schema refusal.

## Completion audit (2026-10-03)

| WP-04 requirement | Current evidence |
| --- | --- |
| RFC 8785 `lab-jcs-v1` | `canonical.rs` uses JCS bytes and domain-separated SHA-256; Rust domain tests and `scripts/verify-jcs-vectors.mjs` pass. |
| Local private durable state | `Store::open` checks absolute private paths and Linux filesystem type; WAL, FULL synchronous and foreign keys are fixed. Store tests reopen assets/revisions, reject future schema and check file modes. |
| Asset-first archive and referential integrity | Asset writes sync the file and directory before metadata insertion. Revision, preparation checkpoint and snapshot reads compare complete indexed references with revalidated asset manifests. Crash and file-size-limit tests show an orphan file cannot become a false committed reference. |
| Schema migration and backup | Versions 1–7 upgrade transactionally after a synced SQLite online backup; tests inspect backups and preserved state for versions 1, 3, 4, 5, 6 and 7. |
| Leases and liveness | PID/start-ticks/boot identity, fencing generation and heartbeat reject live or unverifiable owner takeover; tests cover contention, stale token, expiry and confirmed absent-worker reclaim. |
| Journal intents and recovery index | Append-only CAS versions persist `request_started` and `unknown` across reopen/process exit. Index state is checked against the hashed body. Tests reject blind retry, later-step dispatch, sent-effect pre-write failure and unverified terminal states. |
| Original versus actual snapshot state | The original contract has no after-state field. Schema 8 stores original source/archive/media links separately from an immutable after-state asset plus receipt, bound to the started journal step's approval, payload, session, lineage and expected digest. Reads recheck both assets. CLI list/show expose `unknown` when no after-state is stored. |

The WP-04 durable store boundary is complete. Native effect certification, checkpoint/restore execution, cache pruning and full apply/job modes remain assigned to WP-10–WP-14; this audit does not mark those gates complete.
