# Implementation work package

Read [package dependencies and architecture](README.md) and the task-referenced OP/ALG records before coding.

## WP-10 — checkpoints/model actions

Touch: application backup/model use cases, Anki/export port, snapshot/store. Read ALG-BACKUP, ALG-MODEL and OP-17, OP-52–54.

Steps: scoped verified checkpoint artifacts/receipts, coverage escalation, journaled model creation, manifest reuse/name collision handling, exact shared-model safety. No untested backup endpoint.

Tests: false API success/missing file/truncated package/missing media/scheduling, same-name different manifest, partial model creation and lost response. Done when checkpoint failure guarantees zero dependent mutation and disposable restoration evidence matches claimed scope.

## Completion audit — 2026-10-04

- Scoped, verified checkpoint artifacts and receipts: `linguist_application::backup::create_checkpoint` runs ALG-BACKUP over an injected `CheckpointExporter` port under a held writer lease. It journals one `export_checkpoint` intent with a durable `request_started` before dispatch. A claimed success counts only after the claimed path, size and SHA-256 match the actual create-new temporary file, the package passes container/SQLite/core-schema inspection, every scope entry is present, and a disposable decode restoration test reproduces the same scope. The artifact is then hard-linked create-new, synced and re-hashed, an immutable receipt is stored (store schema 9: `checkpoint_receipts`, append-only `checkpoint_verifications`), and the journal commits. Failures delete the temporary file and record `failed_before_write`; unknown responses record `needs_recovery`.
- Scope verification: `checkpoint::inspect_colpkg_scope` requires each scope note, each card (same note, at least the observed repetitions and review-log rows), each note type (`notetypes` table, or `col.models` on schema 11) and each media name with its SHA-1. `checkpoint::restore_test` decodes the collection and every media file into a private directory below a disposable target, reopens and re-hashes them, repeats the checks and removes the directory.
- Coverage escalation: `plan_coverage` always selects a collection package. A schema requirement adds scheduling, media and schema; `affected` preferences escalate with an explicit reason.
- Fail-closed write gate: `require_checkpoint` checks the execution binding, restoration evidence and its digest, coverage flags, scope membership and group sharing. Cross-group reuse needs a non-zero reuse age, an age within it and an unchanged protected-manifest digest, and it returns the reason. The gate re-hashes the artifact, so a missing or changed file blocks the write.
- Journaled model creation: `linguist_application::model_install::install` reuses only an exact single same-name model, blocks name collisions and duplicates, requires the gate for a collection/scheduling/media/schema checkpoint before creation, stores a pre-state record (`model_operations`) and the journal intent before calling the port, then verifies the read-back. Partial models and lost responses enter `needs_recovery`, block later attempts for that name, and are never deleted. `reconcile` adopts a result only with the exact name, exact manifest and companion evidence naming that model. It closes the operation as not created only when the name is absent and the companion reports `failed_before_write`. It never re-sends.
- Journal rules: `committed` now requires every step verified; `failed_before_write` accepts explicit `observed_failure` steps; reconciliation may move `unknown` to `observed_failure` or `verified`.
- CLI: `backup create` previews coverage and path, and `--apply` fails before any lease, journal, file or Anki request. `backup list` lists receipts with filters. `backup verify` re-verifies a receipt (optionally restore-testing and appending evidence) or checks an unregistered file with an optional scope manifest. `models install` preview lists apply requirements, and `--apply` stays unavailable. No untested backup endpoint is called.

Tests: `tests/checkpoint_writes.rs` covers a verified checkpoint with receipt, restoration evidence, committed journal and cleanup. It covers false API success with no file, a truncated package, size/path claim mismatches, missing media, missing scheduling and missing cards, and rejected versus unknown exports. It also covers invalid requests before any journal, coverage escalation, gate checks (binding, scope, reuse age/digest, changed and missing artifact, unknown receipt) and a content-only checkpoint refused for a schema action. For models it covers zero mutation on checkpoint failure, exact reuse, collisions (fields, CSS, template order, duplicates), journaled creation, partial creation, lost responses with and without effect, a rejected install, and a crash after `request_started`. Store tests cover receipt immutability, invalid receipts, verification append and the new commit/failure rules. CLI tests cover create preview and apply refusal, list filters, registered verify with a restore test and missing/changed artifacts, and unregistered file verification. Real-package evidence is in [native checkpoint scope](../evidence/native-checkpoint-scope-2026-10-04.md).

Evidence: `cargo test --locked --workspace --quiet`, `cargo clippy --locked --workspace --all-targets -- -D warnings`, `cargo fmt --all -- --check`, `python3 docs/cli/validate.py`, `git diff --check` and the two disposable Anki scripts named in the evidence record.

Done criterion: checkpoint failure guarantees zero dependent mutation in the fake-port tests, because model creation calls the gate before any record, journal or port call. Disposable restoration evidence matches the claimed scope for fake packages and for real Anki 25.09.2 packages. It does not yet do so for a live native export, because none exists.

## Known limits — revisit after all packages

- No live native adapter: the companion does not implement the `export_checkpoint` or `install_model` `labMutate` variants, and no Rust transport dispatches them. `backup create --apply` and `models install --apply` return `CAPABILITY_UNAVAILABLE`. All orchestration is verified only with fake ports (WP-03/WP-11).
- No live scope capture: nothing yet builds a scope manifest from the collection under the writer lease, or supplies the current execution binding from a native session. The CLI accepts only a hand-written JSON manifest, and only for preview and unregistered verification (WP-11 apply orchestration).
- Affected-scope packages (deck-scoped `.apkg` with scheduling and media) are not implemented, so every checkpoint is a whole-collection package. It is shared per scope-closed group, but a content-only add still exports the whole collection.
- The restoration test is the CLI's own decode (zstd collection, media files, SQLite reopen), not Anki's importer. It does not prove Anki-level semantic consistency, deck configuration, FSRS state or that Anki would accept the package. An importer round trip is shown only by the evidence scripts for a one-note fixture.
- Scope checks are presence and lower-bound checks. Notes are checked by ID only, not field content. Cards are checked by ID, owning note, repetitions and review-log count at least the observed values; due, interval, ease, queue and memory state are not compared exactly. Note types are checked by ID, not manifest content. Media is checked only for listed names by SHA-1. Collection-wide media completeness is not verified, and `includes_media` relies on the export request's media flag plus the listed files.
- Recovery gaps: there is no reconcile command for checkpoint journals (`recover reconcile`, OP-60, is unavailable). An unknown export leaves its temporary file and a pending journal for manual handling. Crash windows have no automated recovery: after the hard link but before the journal observation (orphan artifact, journal still `mutating`), and after the receipt is saved but before the commit (valid receipt, journal `verifying`). Abrupt termination can leave restoration directories and scratch files, which are removed only on normal return or unwind.
- Model reconciliation has no CLI command and no real operation-evidence source; `ModelPort::operation_evidence` is a port method only. Without companion evidence, an uncertain operation stays `needs_recovery` and blocks that model name indefinitely. There is no documented manual recovery procedure for a partial model beyond "do not use it; it is never deleted".
- Model reuse means exact content equality (name, ordered fields, template names, ordinals and bytes, CSS). Managed provenance is not established, so a user-created identical note type is reused. Template ordinals must come from a native read; AnkiConnect reads alone cannot supply them. Same-name collisions are only blocked; the separately reviewed versioned-name route is not implemented. Schema migration and card generation (ALG-MIGRATE) are out of scope (WP-11).
- Leases and fencing: creation, gate and model install validate a held lease token. They cannot confirm it is the collection-writer lease for the bound collection, and no native owner token or fencing generation is checked.
- Binding comparison covers endpoint, profile/path fingerprints, bridge, lineage and session epoch; `capability_digest` is not compared. Bindings are trusted from the caller.
- Journals for checkpoint and model operations reuse `OperationJournal` by convention. `approval_digest` is prefixed `lab-checkpoint-v1:` or `lab-model-v1:`. `snapshot_id` is the receipt ID for checkpoints and the operation ID (pre-state record) for models. There is no operation-kind field. The store cannot verify that an `observed_failure` really had no effect; it trusts the caller.
- Settings: `backup.reuse_max_age_seconds` is consumed by the application gate, but no CLI command passes it yet. `backup.scope` is only reported in the preview; `--scope` must still be given explicitly. The export port has no CLI-side deadline, and inspection and restoration each get the full `backup.verify_timeout_seconds`.
- Artifacts: the final `.colpkg` is written by the exporter, and its permissions are not forced to 0600. There is no retention or pruning of receipts or artifacts. `backup list` does not re-hash files; deletion or change is detected only by `backup verify` or the write gate. `--since` accepts UTC only, and `created_ms` comes from the caller's clock.
- `backup verify RECEIPT --restore-test-target` needs a writable existing store because it appends evidence. Without a target it opens the store read-only and appends nothing.
- Evidence breadth: real-Anki evidence covers one small note on Anki 25.09.2 only. Large collections, shared or renamed media, profile import hooks, concurrent UI edits and real process-kill crash injection are untested; the crash test panics in-process.
