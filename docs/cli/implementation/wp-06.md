## Completion audit — 2026-10-03

- Provider composition: the shared `linguist-provider` crate supplies the read boundary and the sandboxed helper runner. The dictionary, kanji, image, speech and OCR adapters live in `linguist-dictionary` and `linguist-application`. The CLI uses them; it never imports desktop or QML code.
- Rich dictionary objects: Jisho/Wiktionary entries, senses, forms and raw responses are retained (earlier WP-06 work). Kanji pages keep meanings, on/kun readings, strokes, radical, parts, grade, JLPT, frequency and the raw page.
- Retries, deadlines, semaphores and cache: one deadline covers each read. Origin gates, service semaphores, classified transient retries with Retry-After and the provider cache are shared by every HTTP adapter. The OCR result cache uses the same policy and TTL settings.
- OCR before generation: revamp capture runs OCR on source images under `images.existing_policy=inspect` before plan publication. Generation is refused until OCR exists and its stage-`ocr` reviews are resolved.
- Capability resolution: the engine probe hashes the executable and installed language packs, and the voice config is checked for language and speaker. `doctor --local` reports both. Missing packs and resources fail before state creation.
- Optional adapters: Tesseract, Wikimedia, Jisho kanji and Piper are implemented. PaddleOCR, Ollama vision OCR and vision adjudication, the browser helper, custom image/audio/dictionary endpoints, dictionary audio and `network.proxy_env` return explicit unavailable errors.
- Provider output is data: OCR text, kanji pages and image metadata are extracted as plain text without script content. Prompt-injection fixtures stay verbatim data, and speech text never becomes an argument.

Tests: mock limits, redirects (including private redirect targets), transient vs permanent faults, Retry-After, deadlines, rate history and semaphores; private-address DNS denial; cache policies, TTL, corruption and fingerprints; OCR timeouts, output bombs, decode bombs, missing packs/executables/resources, malformed TSV, region limits, memory-limit propagation and nondefault engine mode/confidence/preprocessing; classification thresholds; OCR review resolution and generation gating; image candidate rights metadata and rejected downloads; Piper stdin, speaker selection, language mismatch, faults and invalid output; and nondefault kanji, image, audio, network, retry, cache and service settings. Existing Ollama tests cover structured-output and unsupported-parameter failures.

Evidence: `cargo test --locked --workspace --quiet`, `cargo clippy --locked --workspace --all-targets -- -D warnings`, `cargo fmt --all -- --check`, `python3 docs/cli/validate.py` and `git diff --check`. The parser was checked against one live Jisho kanji page and the Commons search shape against one live response; the fixtures are reduced synthetic copies of those shapes. Piper was not available, so only fake-engine evidence exists. Preparation does not yet stage kanji, image and speech results; that is WP-07/WP-08. Cache pruning is WP-14.

## Known limits — revisit after all packages

These gaps were left open deliberately and must be closed or re-accepted after WP-16.

- Piper was tested only against a fake executable; no Piper binary or voice was available. Voice license evidence is limited to hashing the model and its config; no license file is checked.
- The Jisho kanji parser and the Commons response handling were each checked against one live response; the fixtures are reduced copies. Upstream markup or API changes fail as `PROVIDER_READ_Schema`; they are not detected ahead of time.
- PaddleOCR, Ollama vision OCR, `classification.vision_adjudication`, the browser helper (`browser.*`, `dictionary.browser_fallback`), custom dictionary/image/audio endpoints, dictionary audio and `network.proxy_env` return explicit unavailable errors and are not implemented.
- Image classification is an uncalibrated layout heuristic (`ocr-layout-heuristic-v1`); the legacy logistic model and user-feedback calibration were not ported.
- OCR reads only the first frame of animated images. Tesseract confidence is engine-specific and uncalibrated.
- Helper sandboxing covers only: no shell, a cleared environment, its own process group, the `RLIMIT_AS` address-space limit, the deadline and the output bound. There is no seccomp, namespace, cgroup or filesystem confinement, so a helper can read anything the user can read. A grandchild that calls `setsid` can escape the group kill. Between reaping the leader and the group kill there is a small PID-reuse window.
- `doctor --local` runs the configured OCR executable (`--version`, `--list-langs`) to probe it.
- OCR runs only during revamp capture under `images.existing_policy=inspect`; authored add has no image input.
- Rate gates and service semaphores are per process; concurrent CLI processes do not coordinate. Ollama keeps its own loopback-only transport with concurrency 1 rather than the shared reader.
- The provider and OCR caches are never pruned or size-limited: `cache.max_size_mb` and `cache.unreferenced_retention_days` are unconsumed until WP-14. TTLs use wall-clock time. A cache write failure is silent.
- Each DNS lookup uses one thread; the public-address check follows fixed IPv4 special ranges and IPv6 `2000::/3` minus documentation space, not the full IANA registry.
- Manual OCR transcription (editing region text) is WP-09 work. Choosing an expression from OCR text accepts only one single-line region of at most 200 characters.
