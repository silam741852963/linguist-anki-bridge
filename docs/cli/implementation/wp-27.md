## WP-27 — card profiles: part-of-speech colours, normalized tags and a three-level domain taxonomy

Status: in progress. Step 1a (tags from the label table), step 1b (colours, on branch `wp27-profiles` until the companion 0.6.0 is live) and step 2 (domains in the enrichment call) done 2026-10-24; see [Progress](#progress).

### Goal

The user's request (2026-10-24):

> The appearance (colour palette, etc.) of the vocabulary and grammar cards must change with the word's type (noun, adjective, etc.). If a word can be used as several types, those sections must be highlighted in the colour of their type, while the main usage keeps the main palette. If a card is missing its type tag, add it; this tag must be LLM-independent. The tags must carry more information: first, a three-level domain chosen by the LLM from a domain list crafted first, backed by usefulness and official classification. Think of other information to store for vocabulary and grammar cards.

Already revamped notes are changed too.

### What the store shows (2026-10-24)

- 5,326 vocabulary documents: 3,865 Japanese and 1,461 English. Every selected sense but one has labels.
- `render::tags` turns **every** label of the selected sense into `lab::pos::<label>`. Jisho labels mix part of speech with field (`Computing`, `Medicine`), register (`Colloquial`, `Honorific or respectful (sonkeigo) language`), script (`Usually written using kana alone`) and notes (`Wikipedia definition`, 4,501 senses). The tags `lab::pos::wikipedia-definition` and `lab::pos::computing` are wrong today.
- English: 279 notes have 2–4 parts of speech among their Cambridge entries (`issue` noun and verb); 41 have none.
- Cambridge entries carry `smart_vocabulary_topic` (1,697 entries), a topic hint for the domain.

### Decisions

1. **One profile per card, in two parts.**
   - The **derived profile** is computed by code from the dictionary entries, the pattern and the tokenizer, at render time, like the WP-19 tags. It is never stored and needs no LLM, so it is always in step with the document.
   - The **judged profile** is chosen by the LLM from closed lists, stored in the document (`profile` in `Vocabulary` and `Grammar`), validated and shown in review. It records the taxonomy version (`domains-v1`).
2. **Part-of-speech classes follow Universal Dependencies v2 (UPOS)**, the cross-language standard, grouped into learner classes. Each class has one colour.

   | Class | UPOS | Japanese labels (Jisho) | English labels (Cambridge) | Colour |
   |---|---|---|---|---|
   | `noun` | NOUN, PROPN | Noun, Noun used as a suffix/prefix, place and name labels | noun, plural noun | blue |
   | `verb` | VERB, AUX | Godan/Ichidan/Suru/Kuru verb, Transitive, Intransitive, Auxiliary verb | verb, phrasal verb, auxiliary verb, modal verb | red |
   | `adjective` | ADJ | I-adjective, Na-adjective, 'taru' adjective, Noun or verb acting prenominally, Pre-noun adjectival | adjective | green |
   | `adverb` | ADV | Adverb, Adverb taking the 'to' particle | adverb | amber |
   | `pronoun` | PRON, DET | Pronoun | pronoun, determiner, predeterminer | teal |
   | `function` | ADP, PART, CCONJ, SCONJ | Particle, Conjunction, Copula | preposition, conjunction | purple |
   | `number` | NUM | Numeric, Counter | number, ordinal number | brown |
   | `expression` | (multiword) | Expressions, Idiomatic expression, Proverb, Yojijukugo | idiom, phrase, Prepositional phrase | magenta |
   | `affix` | (bound) | Prefix, Suffix | prefix, suffix, combining form | slate |
   | `interjection` | INTJ | Interjection | exclamation, Interjection | orange |

   Subclasses are kept for tags and drills (WP-26): Japanese verb group (`godan-ku`, `ichidan`, `suru`, `kuru`), transitivity, adjective type (`i`, `na`, `taru`); English phrasal verb, countability (`[C]`, `[U]`) and verb pattern (`[T]`, `[I]`, `+ to infinitive`) once the Cambridge parser keeps the grammar codes.
3. **A label table, not string guessing.**
   - `resources/taxonomy/labels-v1.tsv` maps each provider label to one role: `pos` (class and subclass), `register`, `region`, `field` (domain hint), `script`, `origin` or `note`.
   - Only `pos` labels make `lab::pos::*` tags. The other roles make their own tags (below).
   - An unknown label is reported by `doctor --labels` and never becomes a tag. Its row is added by hand, with a test.
   - English: Cambridge sense labels are mostly guide words (`money`, `person`: the sense's short meaning), 500 of the 536 distinct English labels. The table lists only the English part-of-speech and note labels; an English label with no row is a guide word and is ignored, not reported. The Cambridge entry's `part_of_speech` metadata comes before the sense labels.
4. **Every card gets a part-of-speech tag, without an LLM.**
   - Vocabulary: selected sense labels. Fallback 1: the labels of another entry that lists the same form. Fallback 2: the tokenizer (`linguist-text`: Lindera IPADIC for Japanese; the Open English WordNet lexicon for English, offline).
   - If all three fail, the card gets `lab::pos::unknown` and a `POS_UNKNOWN` warning, so it is visible and counted.
   - Grammar: the class of the slot the pattern attaches to, read from the pattern and formation tokens (`V`, `V て`, `N`, `N1`, `い-Adj`, `な-Adj`, `Adj`, plain form). `V て ください` is `verb`, `N1 は N2 です` is `noun`, `い-Adj くて` is `adjective`. A pattern with no slot (どうやって, なかなか, ぜひ) takes the tokenizer class of its own words. A pattern with several slot kinds takes the first one as its main class and lists the others.
5. **Colour follows the main class; other uses are highlighted in their own colour.**
   - The card accent (`--lab-accent`, `--lab-accent-soft`) comes from the main class: the class of the selected sense, or the grammar pattern's main slot.
   - The Meaning panel groups senses by class. The group that holds the selected sense keeps the main colour. Each other group (`issue` as a verb on a noun card) gets a header chip and a left border in its own colour. A sense with two classes (`Noun; Suru verb`) shows one chip per class.
   - The colours of a grammar card's other slot kinds are shown on their formation tokens (`V` in red, `N` in blue).
   - Implementation: the template adds `data-tags="{{Tags}}"` to the card root, and the CSS selects the accent with `[data-tags~="lab::pos::noun"]`. Sense groups carry `lab-pos-<class>` classes in the rendered Meaning HTML. Templates and CSS change, but fields do not, so no full sync is needed for the colours.
   - Correction (2026-10-24): a template or CSS change is a model change for apply. Apply reuses a model only when the collection's note type matches the managed manifest exactly (fields, templates and CSS), and refuses a same-name note type that differs (`MODEL_NAME_COLLISION`, never overwritten). A staged render also carries the model, and plan validation compares it with the current render (`STAGED_RENDER_MISMATCH`). The colours therefore need (1) a `models update` operation that rewrites the templates and CSS of a managed note type in place, with the same fields, under a checkpoint and journal, and (2) a new revision of every plan staged with the old render. They ship at a drained point of the campaign, not mid-batch.
   - Each class has a light and a dark token pair. A unit test checks WCAG AA contrast (≥ 4.5:1 for chip text, ≥ 3:1 for borders) against the panel in both modes. A test also checks that the three most common pairs (noun/verb, noun/adjective, verb/adverb) stay apart for the common colour-vision deficiencies.
6. **Domains: a three-level taxonomy, crafted once, chosen by the LLM.**
   - The taxonomy is [wp-27-domains.md](wp-27-domains.md), shipped as `resources/taxonomy/domains-v1.json`. It joins three official classifications:
     - everyday life: the Council of Europe *Threshold Level* (1990) specific-notion themes, which the CEFR builds on;
     - specialist fields: UNESCO ISCED-F 2013 broad, narrow and detailed fields;
     - abstract words and grammar meaning: the *Threshold Level* general notions.
   - Every path has exactly three levels, for example `food::meals::breakfast` or `health-welfare::health::medicine`. Each node has an id, an English label and its source reference; level-1 nodes also have a one-line scope note.
   - Each card gets **one primary domain and at most two secondary domains**, all of them leaf paths. Function words and grammar usually take a `notions::*` path.
   - Rule for life and specialist fields: a word a layperson uses in daily life goes to the everyday-life tree (風邪 → `health::illness::common-illness`); a technical term goes to the specialist tree (心筋梗塞 → `health-welfare::health::medicine`). The JMdict field label and the Cambridge SMART Vocabulary topic are given to the LLM as hints, through the mapping in [wp-27-domains.md](wp-27-domains.md#hints).
   - Validation: each id must exist in the shipped version. If the LLM ignores a field hint, a warning `DOMAIN_HINT_IGNORED` is shown in review (not an error: the hint is about the entry, the card about one sense).
   - Tags: `lab::domain::<l1>::<l2>::<l3>` for the primary domain, and `lab::domain2::…` for secondary domains, so Anki's tag tree browses by level.
7. **Where the LLM call happens.**
   - Notes not yet revamped: the enrichment prompt returns the judged profile in the same call. This costs no extra call from the campaign budget.
   - Notes already revamped: a new `classify` stage sends batches of 25 compact notes (expression, reading, selected sense, the other classes, field hints, examples' first line) with the taxonomy. It returns profiles only, through the ordinary review and apply. 18,000 notes take about 720 calls, run after the WP-24 campaign or in its idle quota.
8. **Already revamped notes.** `revamp retag` builds a plan revision that only re-renders: new Meaning HTML with class groups, new tags, the judged profile when present, and no generation. It goes through the ordinary review and apply in campaign batches. Old `lab::pos::<raw label>` tags are removed by apply, which owns the `lab::` namespace.
   - Correction (2026-10-25, the user's choice): a plan revision cannot carry it. Apply refuses a note that changed since its capture (`APPLY_SOURCE_CONFLICT`), which every applied note did, and a split child has no source note, so applying its plan again would create a second note. The command is `notes retag` (OP-88), a direct operation like `models update`: a note is rewritten only while it still equals what its latest apply wrote, from the stored document, with an exact `restore_note` under a checkpoint, a snapshot and the apply journal. There is no review step, because nothing is generated; the preview lists every change first.

### Profile fields

The derived fields are computed at render time. The judged fields are stored in the document and need the LLM. ✓ marks what this package delivers; the other rows are recorded for later packages.

| Field | Vocabulary | Grammar | Kind | Tag | |
|---|---|---|---|---|---|
| Part-of-speech class and subclass | from labels, tokenizer | from pattern slots | derived | `lab::pos::<class>[::<sub>]` | ✓ |
| Other classes of the word | other senses and entries | other slots | derived | `lab::pos-also::<class>` | ✓ |
| Register | Jisho and Cambridge labels (colloquial, formal, honorific, humble, polite, slang, archaic, dated, derogatory, literary) | chosen: spoken, written, polite, plain, formal, casual | derived (vocabulary), judged (grammar) | `lab::register::<r>` | ✓ |
| Region | Cambridge UK, US, AUS; Jisho dialect labels (Kansai-ben) | – | derived | `lab::region::<r>` | ✓ |
| Word origin (ja) | wago, kango, gairaigo, wasei, mixed: from the Wasei label, katakana script, and the on/kun reading of each kanji | – | derived | `lab::origin::<o>` | ✓ |
| Script note (ja) | `Usually written using kana alone` | – | derived | `lab::script::kana` | ✓ |
| Level | JLPT (Jisho), common; CEFR when Cambridge shows it | JLPT, lesson (exists) | derived | `lab::jlpt::*`, `lab::cefr::*` | ✓ |
| Attaches to and required form | – | `V て`, `V ない`, `V dictionary`, `V た`, `V-ます`, plain form, `N の`, `い-Adj`, `な-Adj`, sentence | derived | `lab::attach::<slot>`, `lab::form::<form>` | ✓ |
| Domain | primary + up to 2 secondary | primary (usually `notions::*`) | judged | `lab::domain::*`, `lab::domain2::*` | ✓ |
| Communicative function | – | *Threshold Level* functions (request, permission, obligation, offer, condition, cause, contrast…), 1–2 | judged | `lab::function::<group>::<fn>` | ✓ |
| Connotation | positive, neutral, negative | – | judged (derived when labelled derogatory or disapproving) | `lab::connotation::<c>` | ✓ |
| Transitivity partner (ja) | 開く ↔ 開ける: proposed by the LLM, kept only when Jisho lists the partner with the opposite transitivity | – | judged, verified | shown on the card under Related | ✓ |
| Pitch accent (ja) | needs a licensed source (OJAD is not one) | – | – | – | later |
| Frequency band | needs JMdict priority tags (news1, ichi1, nfXX) from the local JMdict of WP-25 | – | derived | `lab::freq::<band>` | WP-25 |
| Prerequisite patterns | – | other grammar notes this pattern builds on (たら needs the た-form) | judged | – | later |
| Learner history | flags, lapses and confusions from `cardsInfo` | same | derived (read-only) | – | WP-26 stats |

Tag namespaces stay under `lab::`. Apply owns them: it adds and removes them, and never touches the user's own tags.

### Steps

1. **Taxonomy and labels.**
   - Write `domains-v1.json` from [wp-27-domains.md](wp-27-domains.md), and `labels-v1.tsv` from every label in the store (723 distinct labels today).
   - Unit tests: unique ids, exactly three levels, every hint target exists, every stored label has a row.
2. **Core.**
   - `Profile` types (derived and judged), the label resolver and the grammar slot reader.
   - Profile validation (closed lists, ids, at most 2 secondary domains, transitivity partner check).
   - The new tags, which replace the raw `lab::pos::<label>`.
3. **Render.** Sense groups by class in the Meaning HTML; coloured formation tokens on grammar cards; `data-tags` on the card roots; palette tokens in `vocabulary-v3.css`, `grammar-v4.css` and the English template, with the contrast test.
4. **Tokenizer fallback.** Use `linguist-text` from WP-25 for the class of words with no label. If WP-25 is not built yet, ship the label resolver first and emit `lab::pos::unknown` until it is.
5. **Application.**
   - Profile fields in the enrichment schema and prompt.
   - The `classify` stage with batched calls.
   - `notes retag` (decision 8, correction).
   - `doctor --labels`.
6. **Cards checked** in real Anki templates in light and dark mode at phone width: one noun-only card, `issue` (noun card with a verb group), a Suru-verb noun, a grammar pattern with two slot kinds.
7. **Live.**
   - Run `notes retag --all` over the applied notes, at a pause of the campaign.
   - New campaign batches carry judged profiles.
   - Then run `classify` over notes revamped before this package.
   - Spot-check 50 domain choices per tree.

### Done when

- Every vocabulary and grammar note has exactly one `lab::pos::<class>` tag, made without an LLM; `lab::pos::unknown` is under 1%.
- No tag in the `lab::pos::` namespace comes from a non-part-of-speech label.
- Cards show the main class colour and the other classes in their own colours, in both modes, and pass the contrast test.
- Every note has a primary domain from `domains-v1`. In the spot check, at least 90% of domain choices are judged right.

### Environment and safety

- Colours change only templates and CSS: no new field and no full sync. The judged profile lives in the store's document, not in an Anki field.
- `notes retag` changes field HTML and `lab::` tags of applied notes in place, under a collection checkpoint and the apply journal. Card schedules, decks and the note type are not touched.
- Anki is never started by the agent.

**Step 5a, 2026-10-25: `notes retag`.**
- `linguist_application::retag`: `latest_by_note` reads every apply operation and keeps each note's latest one (a created note's ID comes from the receipt); a note whose latest operation was restored or is unresolved is skipped (`RETAG_NOT_APPLIED`).
- `propose` reads the note through the companion and compares it with what that operation wrote (fields and sorted tags). A note edited since is `RETAG_NOTE_EDITED` and never written. Otherwise the stored document is rendered again and the tags made as apply makes them; the verdict is `change` (fields, tags added and removed), `current`, or a skip (`RETAG_NOTE_MISSING`, `RETAG_RENDER_BLOCKED`, `RETAG_MODEL_CHANGED`).
- `retag` writes one change: the note read again (`RETAG_NOTE_CHANGED` before the journal), the checkpoint gate, an apply-operation record for the same plan item and approval, a fresh snapshot, a journaled `restore_note` with the exact fields and tags and every card kept in its deck, the companion call, the read-back and a receipt. `apply::commit` reads back a `restore_note` step. Being an apply operation, it is found by the next retag, settled by `recover reconcile`, and undone by `snapshots restore` (tested).
- CLI `notes retag [NOTE_ID...] [--all] [--limit N] [--fields] [--apply]`: one checkpoint per run for the changed notes; the run stops at the first operation that is not committed.
- Preview over the live collection (2026-10-25, 4,159 notes an apply wrote): 4,066 change (Meaning 3,847: the `lab-pos-*` classes; UsageExamples 60: an empty example item dropped by a later fix; Pronunciation 2: kana spacing), 21 current, 67 restored, 5 `RETAG_RENDER_BLOCKED` (`AUDIO_NOT_FOUND`: their audio evidence fails today's validation), and no note edited since its apply. The preview of all notes takes about 6 minutes.

### Known limits — revisit after all packages

To be filled at completion. Expected:
- `notes retag` skips a note whose stored document no longer passes today's validation (`RETAG_RENDER_BLOCKED`, 5 notes with `AUDIO_NOT_FOUND`); they need a redraft.
- A retag carries the approval of the document it renders; the new render itself is not reviewed.
- A retag writes one note per journaled operation (about 4,000 operations for the collection).
- The domain is judged per selected sense, not per word.
- The tokenizer fallback gives a class without a subclass.
- Grammar register and function come from the LLM only.
- `plans regenerate --stage generation` does not list `profile`: a profile is cleared by a review rejection only (step 3 adds the classify pass).
- A reply's invalid primary domain leaves the note without a profile and is not logged in `rejected-<provider>.jsonl`; the backfill finds it by the missing profile.
- The leaf list costs about 3,000 prompt tokens per call (cached prefix on Codex).
- Grammar formation tokens (`V` in red, `N` in blue) are not coloured yet; only the card accent follows the grammar class.
- Notes applied before step 1a keep their raw `lab::pos::<label>` tags (no colour or a wrong one) until `notes retag` runs.
- Tritan simulation keeps noun and adjective only ΔE 15 apart in dark mode.
