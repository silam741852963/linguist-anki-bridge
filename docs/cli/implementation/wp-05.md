## Completion audit — 2026-10-03

- Deterministic ID selection: query/deck preparation freezes the observed, sorted match set, original selector and limit; zero query matches create no state. `notes list/count` require a complete unique explicit-ID match. Deck-list cursors bind the exact inventory. See `jobs.rs`, `selector.rs`, and CLI read tests.
- Bounded reads: Anki adapter limits response bytes and note/card batches; source capture caps aggregate payload/media sizes and reference counts. Deck-model scan caps notes at 100,000 and reads batches of 100.
- Complete read-port archive: raw field values, tags, read-port note/card payloads, model fields/templates/CSS, source task mapping, media discovery references/issues, and original media bytes or explicit missing receipts are retained under content hashes. Stage revalidates source assets and flags meaningful unmapped fields. This is exact reproduction of the read-port observations, not a native atomic snapshot or review-log claim.
- Source/target mapping: `decks map` checks existing regular decks, model fields/templates, required roles and task assignments, then atomically saves a backed-up local config. `decks unmap` is idempotent. No Anki mutation command is used.
- Duplicate candidates: exact compared fields, other sense/use, other language and unresolved hits are distinct review labels. Collection/target-deck scope is honored without authorizing `skip_exact` or apply.
- Read commands: deck list/show, model list/inspect, note list/show/count and media inspection return profile-pinned evidence. Fixtures cover the inventory shapes named above, malformed media and missing assets.
