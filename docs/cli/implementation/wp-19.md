### Completion audit 2026-10-08

**Model and rendering.** `model::vocabulary()` is `Linguist Vocabulary v3` (9 fields, CSS in `vocabulary-v3.css`, templates Comprehension 0, Production 1, Spelling 2). `render` produces:

- Meaning: the selected entry's sense list (`lab-selected`) with every occurrence of the expression masked as `〜`.
- UsageExamples: Usage, Nuance, Collocations and Examples, with the expression highlighted.
- Kanji: per-character cards from `kanji_details`, with the `kanji_stroke` GIF.
- Pronunciation: Pronunciation, or else Reading.

`render::tags` derives `lab::lang`, `lab::explain`, `lab::kind`, `lab::task`, `lab::jlpt`, `lab::common`, `lab::pos` and `lab::has::*`; apply adds them to the note. `escape` now matches the HTML text serializer (`&`, NBSP, `<`, `>`), so a note saved in Anki's editor reads back byte-identical. The cards were rendered through real Anki templates and checked in light and dark mode.

**Validation.** Vocabulary needs no text cues. Spelling needs a Pronunciation/Reading or a selected audio (`SPELLING_CUE_MISSING`). A Pronunciation equal to the written form is `ANSWER_LEAK`. The semantic corpus vocab-add fixtures were rewritten for these rules.

**Enrichment.**

- `kanji.stroke_order` fetches KanjiVG-based GIFs from `mistval/kanji_images` (signature-checked; a miss is a warning).
- `audio.provider=dictionary` stages a JapanesePod101 native recording as a reviewed candidate. The placeholder clip is rejected by digest. The kana comes from the reading, or else from the single reading all exact dictionary entries agree on.
- Stroke GIFs never suppress the picture search.

**Generation.** The `builtin:vocabulary-v3` prompt and schema add `nuance` (≤3, never the word itself) and `collocations` (≤4). The LLM input:

- leaves out raw provider archives, media and kanji evidence, non-exact dictionary entries, `*_json` metadata, and fields a reviewer dropped;
- otherwise exceeded `num_ctx`.

**Engine certification (RI-06 gate).** `doctor --ollama --certify` runs eight probes:

- calibration;
- input preservation at about 80% of the input budget;
- structured output;
- determinism;
- overflow refusal with `truncate=false`;
- the `num_predict` cap;
- no thinking;
- identity stability.

Runs are recorded immutably (store schema 14). A draft whose engine identity matches the newest passed run, with the same live Ollama version, gets `GENERATION_ENGINE_CERTIFIED` (warning) instead of `GENERATION_ENGINE_UNVERIFIED`. Certified on 2026-10-08 for Ollama 0.40.0 with `gemma4:12b`, `num_ctx` 8192, output 2048, temperature 0, seed 0.

**Review.** `source_field_dropped` resolves `SOURCE_UNMAPPED_FIELD_REVIEW` while the field is archived. Before this, a revamp that left obsolete fields unmapped could never become ready.

**Companion 0.2.0.** Accepts the v3 field set; v2 is still accepted. It was installed into the user's Anki by updating the add-on files after a normal window close.

### Known limits — revisit after all packages

- **Collection replacement.** A full-sync download that replaces the collection silently undoes verified restores; local receipts then block a second restore (`RESTORE_ALREADY_RESTORED`). The stale v2 歩留まり note 1791366792727 came back this way. Detection of replacement through the session identity and a re-restore path are missing (extends RI-11). Every schema change (model install, note-type migration, restore) needs a full sync, and the user must choose Upload.
- **Regeneration with a sense.** `plans regenerate --stage generation` clears every decision, including the digest-bound sense choice, and generation then refuses (`GENERATION_SENSE_SELECTION_REQUIRED`). Workaround: a fresh plan, or resolve the sense before `plans generate`. Dependency-specific rebinding of decisions is missing.
- **Decision churn.** Decisions are bound to the document digest, so a content-changing decision (sense, media role) reopens earlier ones; reviews must be ordered or repeated.
- **Picture search.** Wikimedia search uses the expression; for abstract Japanese terms (歩留まり) it returns unrelated images. Searching by the selected English meaning is not implemented.
- **Nuance quality.** `gemma4:12b` often finds no real near-synonym; the self-contrast filter drops the word itself. No synonym source (thesaurus, JMdict cross-references) feeds the prompt beyond `related_entries`.
- **Hán-Việt.** Sino-Vietnamese readings from old notes are sent to the LLM as source context but not rendered; no Hán-Việt dictionary exists.
- **Legacy content fields.** `production_prompt`, `spelling_prompt` and plain `kanji` text stay in the document schema and the CLI flags but are never rendered by v3. Old v2 notes keep rendering only until revamped.
- **Certification scope.** Probes use synthetic canary text, not Japanese learning content; determinism is checked once and may hit Ollama's prompt cache. A certification is bound to endpoint, model digest, `/api/show` digest, budget, temperature and seed. Ollama's version is checked at publish time, which costs one extra request.
- **Audio source.** JapanesePod101 coverage is incomplete and its terms of use are not recorded beyond attribution; no license field is set.
- **Release check.** The desktop scenarios and `release-check.py --msrv --release-build --benchmark` were not rerun for this package; the verify scripts (`verify-template-cards`, `verify-native-apply`, `verify-native-restore`, `verify-native-forward-mapping`, `verify-native-inspection`) pass against Anki 25.09.2 with the v3 manifest.
