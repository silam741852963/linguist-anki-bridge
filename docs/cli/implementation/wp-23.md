## WP-23 — grammar v4 card and split units that keep the source's schedule

Status: complete 2026-10-10 (see the completion audit).

### Goal

The user's feedback on the WP-22 cards (2026-10-10):

> - Pattern: keep.
> - Meaning: keep, remove the Vietnamese explanation.
> - Formation: keep.
> - Example: keep; all examples go here.
> - UsageExamples: remove; examples move to Example, usage to a dedicated Usage field, nuance to a dedicated Nuance field.
> - Remove ExercisePrompt, ExerciseAnswer and EnableApplication.
> - Audio is generated for every example, each with its own play button.
>
> A revamped card keeps its review date information instead of being treated as a brand-new card, for vocabulary and grammar.

### Where things stand

- `Linguist Grammar v3` (WP-22): Pattern, Meaning (English gloss plus the source's Vietnamese line), Formation, Example (the first example, the Recognition cue), UsageExamples (usage, nuance, every example), ExercisePrompt, ExerciseAnswer, Audio (a VOICEVOX reading of the first example), EnableApplication; templates Recognition and Application.
- A revamp keeps the source note's cards, so a single-unit revamp keeps its history. A **split** keeps the history only on the anchor: every other unit is created as a fresh note with new cards (`split.rs`, `grammar.rs`: "Siblings are new notes: fresh scheduling"). In the user's collection:
  - grammar: 6 anchors kept history; 32 split units are new cards;
  - vocabulary: 5 split groups from WP-20 left 19 split units as new cards.
  All 51 of these units are still unstudied.

### Decisions

Taken from the feedback; no question was left open.

1. **Grammar v4 model.** `Linguist Grammar v4`, fields Pattern, Meaning, Formation, Example, Usage, Nuance. One template, Recognition. v3 stays readable as a revamp source.
2. **Example** lists every example: the sentence with the pattern highlighted, its translation and its own `[sound:]` play button.
3. **Audio per example.** Enrichment synthesizes one reading per example. Each reading is its own audio candidate with its own review; a selected reading renders after the example it speaks. There is no Audio field.
4. **Front.** Pattern only. An example on the front would bring its sound along: Anki plays every sound of a side, including sounds hidden with CSS.
5. **Meaning** is the explanation-language gloss only. `source_meaning` stays in the document (and the source archive) but is not rendered.
6. **No Application task for grammar.** Grammar documents request Recognition only; `learning.grammar.application=true` is refused, and a grammar document requesting Application is a validation error.
7. **Split units inherit the source's schedule.** A split unit created as a new note copies, card by card, the scheduling state of the source card mapped to the same task (type, queue, due, interval, ease factor, learning steps, FSRS memory state). Its review count, lapses, flags and review log stay empty: the card was never reviewed itself, so rollback still sees it as unstudied. The copy is part of the native `create_note` effect, with the source card's scheduler as a precondition, and the read-back verifies it.
8. **The user's 51 split units** get the inherited schedule by rolling back each split group and applying it again (grammar: on the v4 model); no separate write path is added.

### Steps

1. Core: v4 model, templates, CSS, render (Example with per-example sounds, Usage, Nuance), validation (no Application), tags unchanged.
2. Enrichment: one audio candidate per example without audio; `AUDIO_CANDIDATE_REVIEW` per example; resolve-batch handles several audio reviews.
3. Companion 0.4.0: v4 field set, `inherit_schedule` on `create_note`; `VERIFIED_COMPANIONS`.
4. Apply: split units compute the inheritance from the anchor's reviewed task map and a fresh observation of the source note; the desired read-back includes the inherited scheduler.
5. Tests (core, application, companion, desktop scenarios), corpus, verify scripts, docs.
6. User's collection: install v4; for each WP-22 grammar group and the 〜そうです note, roll back, regenerate audio, re-review, apply on v4; for each WP-20 vocabulary group, roll back and apply again. Check anchors' history unchanged and split units' schedule equal to their source card's.
7. Hand-off: review sheet, full-sync reminder (Upload), completion audit, known limits, release check, commit and push.

- Desktop scenarios and verify scripts pass with v4 and inheritance.

### Known limits — revisit after all packages

- **節 (anchor 1694854849068) not redone.** Its rollback refused with `RESTORE_FIELD_CONFLICT:Audio`, `RESTORE_FIELD_CONFLICT:UsageExamples`: the anchor was changed after its split by a later WP-20 apply, and rolling back would undo that. Its one split unit (1791526873762) stays a new card. A tool to set a unit's schedule without rolling back the group does not exist.
- **Schedule, not history.** Inherited cards have the source card's due date and interval but no review log, zero repetitions and zero lapses; Anki's card info and statistics show them as never reviewed, and FSRS "reschedule on change" would recompute them from an empty log. Leech counting starts at zero.
- **Inheritance is per split, not per revamp.** It applies only to units created by a split group; a separately added note on the same pattern is unaffected. The anchor's task map decides which source card a task copies; a task with no source card (e.g. Spelling when the source had no third card) stays new.
- **Back-side autoplay.** Anki plays every example reading on the back in sequence unless the deck's options turn automatic audio off; there is no per-template switch.
- **Front without an example.** The Recognition front shows the pattern only, a change from the approved v3 design, because a front example would also play its sound.
- **Readings not listened to.** 162 VOICEVOX readings were selected without listening; each reads the exact sentence text (kanji readings by VOICEVOX).
- **Re-review on redo.** Rolling back and re-applying re-reviewed every fact of the WP-22 plans with the same decisions (`facts.py`); `resolve-batch` did not re-apply decisions it had not sent, so a second batch was needed after the native-history decision reopened media roles.
- **Checkpoint per write.** Each rollback and apply exports and verifies a 3.6 GB checkpoint (~12 min with Anki's export); about 25 were written today (backups directory now ~300 GB). `backup.reuse_max_age_seconds` cannot reuse one across writes.
- **v3 notes with Application cards** cannot migrate to v4 (`APPLY_MIGRATION_DROPS_CARD`); none remain in the user's collection.
- **Companion compatibility.** `inherit_schedule` needs companion 0.4.0; an older companion refuses the create body before any write, with a body error rather than a capability message.
