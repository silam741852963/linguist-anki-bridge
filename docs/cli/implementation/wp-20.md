### Decisions to ask the user at the start (one question each, with a recommendation)

1. **Multi-word notes** (about 4 purple notes). Options:
   - (a) keep one note: the first word becomes the expression and the others go into Nuance as authored contrasts (needs a typed way to author nuance — add `nuance` to `plans edit`);
   - (b) split into one note per word: the first keeps the history, the others are new notes; this needs a vocabulary split like `plans split-grammar`;
   - (c) skip them.
   - Recommend (a): it keeps the user's grouping and their study history.
2. **Image-only Word fields.** The expression must come from somewhere. Options:
   - OCR: the Tesseract `jpn` and `vie` packs are missing; only `eng` and `osd` are installed. The user would run `sudo pacman -S tesseract-data-jpn tesseract-data-vie`; do not install system packages yourself.
   - The Ollama vision model (`ocr.engine=ollama`, `llm.vision_model=llama3.2-vision:latest`, installed).
   - The user types the words.
   - Recommend the OCR packs (they also unblock EV-11 and WP-22).
3. **Hán-Việt on blue cards.** v3 dropped PersonalNotes, so the Extra field's Sino-Vietnamese readings are only sent to the LLM and not shown. Offer a "Hán-Việt" line in each kanji block, taken from the source Extra field per character (parse `Chars( components )` groups), shown only when it maps cleanly. Recommend asking after the user reviews the first five notes.

### Steps

1. **Prerequisites.**
   - The user's Anki is running with companion 0.3.0 (`labCapabilities` reports `0.3.0`).
   - Ollama is certified: if `curl -s localhost:11434/api/version` differs from the last certification (0.40.1), run `target/lab/v3.sh doctor --ollama --certify`.
   - At least 200 GB is free.
   - Read the WP-19 known limits.
2. **Per-note facts.** For each note, record:
   - the Word field (text or image);
   - the picture filenames;
   - whether each picture is an illustration or a dictionary or text screenshot — look at each file under `~/.local/share/Anki2/User 1/collection.media/`;
   - the audio files;
   - the Extra text;
   - the card IDs with their reps, interval and due date (cardsInfo), saved before any write.
3. **Pilot five notes** (two blue, two purple, one with a screenshot picture), one at a time, using the WP-19 single-note flow:
   - `target/lab/v3.sh --set "purposes.japanese_vocab.fields=$(cat target/lab/wp19/pw-fields-v3.json)" --set "purposes.japanese_vocab.source_model=2. Picture Words" vocab revamp --note-id N`;
   - `target/lab/wp19/gen.sh "$PWD/target/lab/v3.sh" PLAN SENSE_WORD` (resolves pre-generation reviews, runs certified generation, prints content);
   - read the generated content yourself and reject wrong facts with `LAB_REJECT=nuance` (or `usage`, `collocations`), plus the other driver knobs: `LAB_ARCHIVE_FILES="Screenshot (N).png|…"` for screenshot pictures, `LAB_IMAGE_PICK=digestprefix|dictionary` to choose a candidate, `LAB_AUDIO_PICK=decline` to keep the user's own recording;
   - `target/lab/wp19/apply.sh CLI PLAN --accept-schema-change`;
   - render the backs with `target/lab/wp19/preview2.py` + `shot.py` and look at them.
   - Ask the user to review the pilot in Anki (`flag:4 or flag:7`, `edited:1`) before doing the rest.
4. **The rest as batches** with the WP-21 path: blue and purple in batches of about 10, one checkpoint per batch.
   - Every picture decision is made by looking at the image.
   - Every generated fact is read before it is verified; reject what is wrong.
5. **Verify after each batch:**
   - card IDs, reps, intervals and due dates are unchanged;
   - every `src=` and `[sound:]` reference exists in the collection media folder;
   - the model is v3 and the deck is unchanged.
6. **Hand-off for feedback.**
   - Write a review sheet as an artifact (a page): one row per note with the expression, what changed (pictures replaced or kept, audio, rejected facts), and anything you were unsure of.
   - Tell the user to search `flag:4 or flag:7` in the Anki browser.
   - Remind them to choose **Upload** on the next full sync.
7. **Feedback loop.**
   - Turn the user's comments into code fixes (render, prompt, parser) or per-note re-revamps.
   - Record them in a completion audit and an exhaustive **Known limits** section in this file.
   - Commit and push.

### Done when

- The review sheet is published, and the user's feedback is recorded and addressed.
