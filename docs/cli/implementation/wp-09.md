## Completion audit — 2026-10-03

- Revision-aware changes: `plans edit` (typed patch, or `--editor` with a private typed draft), `plans resolve` (typed, fingerprint-bound decisions), `plans generate` and the new `plans regenerate` all require the latest revision and digest. Stale bases conflict, and every change publishes an immutable child.
- User edit ownership: regeneration replaces only output its stage produced, judged by provenance: generated evidence, dictionary-provenance kanji, unselected candidates and dictionary entries. Edited, authored, captured and reviewed values are reported as protected and are cleared only when named with `--overwrite FIELD`. The default mode is a no-write preview; `--use-current-settings` executes with a newly frozen fingerprint.
- Deterministic, sanitized rendering, diffs, structural and semantic validation, warning acceptance and immutable content approvals existed before WP-09 and are reused unchanged. Approval never authorizes writing.
- Exports: `plans export` (v1 refused as unrepresentable, private archives opt-in) and the new `snapshots export` both use the shared create-new, checksummed bundle writer. Snapshot bundles are marked as private note content and not a collection backup.
- Listing: `plans list --status ready|needs_review|invalid --workflow vocab_add|vocab_revamp|grammar_add|grammar_revamp|mixed` returns payload-free summaries of latest revisions.
- Readiness with ordinary commands: a CLI test takes a vocabulary add and a grammar add from `needs_review` to approval using only `plans show --issues-only`, the offered decision templates, `plans resolve` and `plans approve`. Add/revamp receipts list next commands.

Tests: `tests/review_workflow.rs` covers enrichment regeneration (preview without writes, stale base, replaced kanji, parent unchanged, protected and overwritten edits, invalid overwrite fields), generation-stage clearing of generated content only, dictionary regeneration that keeps the reviewed meaning while reopening sense review, snapshot export, editor drafts and safe command splitting, and plan summaries. `tests/ollama.rs` covers generation regeneration replacing generated usage and keeping authored fields. CLI tests cover review-to-readiness for both add workflows with list filters, editor apply/abort/stale conflict and draft cleanup, regenerate preview/stale/unknown stage, and snapshot export of a missing snapshot. Existing tests cover stale edits, invalid decision fingerprints, approval invalidation by semantic change, leak/empty-task blocks, v1 export refusal and private export disclosure.

Evidence: `cargo test --locked --workspace --quiet`, `cargo clippy --locked --workspace --all-targets -- -D warnings`, `cargo fmt --all -- --check`, `python3 docs/cli/validate.py` and `git diff --check`.

## Known limits — revisit after all packages

- Revamp workflows cannot reach readiness yet: `SOURCE_NATIVE_HISTORY_REVIEW` cannot be resolved until the native bridge proves task/history mapping (WP-03/WP-10). Only the two add workflows were proven to reach approval with ordinary commands.
- `plans regenerate` covers the dictionary, enrichment and generation stages only. OCR, segmentation, capture and split regeneration are not available. Generation regenerates one `--item-id` per call. Any regeneration clears every decision on the affected item, rather than walking a fine-grained invalidation graph.
- Ownership detection relies on per-field provenance evidence. Content generated before generated-evidence tagging existed, or edited outside typed intents, cannot be told apart and is treated as owned (protected).
- Dictionary regeneration always protects the selected meaning, sense key and reading unless overwritten, so a changed dictionary reopens sense review instead of re-selecting automatically.
- `--editor` exposes only the typed patch fields (Meaning, Reading, Pronunciation, Usage, Kanji, Formation, Source) and personal notes. Cues, media, identity and tasks still need typed decisions or other commands. The editor runs with inherited terminal I/O and no timeout. VISUAL/EDITOR splitting is a small quote-aware splitter without variable expansion. An unchanged draft publishes nothing, and a malformed draft fails without saving anything.
- `plans list` filters revalidate the latest revision of each plan found within `--limit` revision rows; the limit counts revision rows, not plans. There is no cursor pagination and no purpose filter (add plans do not record a purpose). The workflow is inferred from source kinds.
- v1 export is always refused; no v1 mapping exists. Plan exports with private archives include the complete plan (credentials are only ever stored as environment-variable names). Snapshot exports include originals, archives, media and the after-state receipt, but not the separately stored after-state evidence assets. Snapshots are only created once apply exists (WP-10/WP-11).
- Approval is content approval only. Apply authorization, binding checks and checkpoint coverage belong to WP-10/WP-11.
- Next-command strings assume the installed binary name `linguist-anki-bridge`.
