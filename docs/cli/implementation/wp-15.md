# Implementation work package

## WP-15 — release/UX

Touch: packaging/build features, scripts/README, versioned command examples. Verify no Qt build requirement for CLI. Produce release binary/checksums and reproducible locked dependency build; do not auto-install it into the user's environment.

Tests: implement all [release gates](../decisions/release-gates.md), including 120 semantic/model fixtures and final purpose presets; fresh local config/help/offline usage, pipes/JSONL/Unicode/SSH/no terminal, interruption exits, four complete disposable prepare→review→apply→restore scenarios, conservative large batch/free-space behavior, current Rust/Python compatibility tests relevant to reused code. Existing integration tests that require UI stay separate and do not prove CLI behavior.

Done when every OP handler has meaningful coverage, all fixed invariants and recovery rows pass, actual technology versions recorded, and optional dependency messages explain the next step. Publish no claim of fully safe revamp if native migration/restore evidence is absent.

## Completion audit — 2026-10-05

WP-15 is implemented. Release evidence is in [release-2026-10-05](../evidence/release-2026-10-05/README.md), written by `python3 scripts/release-check.py --date 2026-10-05 --msrv --release-build --benchmark`. All 34 commands exited 0. Gates: EV-01, EV-05, EV-06, EV-08, EV-10, EV-12 and EV-13 **pass**; EV-02, EV-03, EV-04, EV-07, EV-09, EV-11 and EV-14 are **blocked**, each with a failure code and the partial checks that ran (see the limits below). Because EV-14 is blocked, no full CLI release is claimed. In particular, no claim is made that a revamp of a real collection is safe: the shipped CLI has no native write path.

Packaging and build:
- `scripts/release-build.py --verify-reproducible --clean` builds `cargo build --locked --release -p linguist-cli` twice from empty target directories. It uses SOURCE_DATE_EPOCH (the HEAD commit time) and remapped paths, and compares the two binaries: the binaries were byte-equal (SHA-256 `a1de2354…f8c8fdf3`, 301 s for both builds).
- It refuses a dirty tree and any Qt/QML crate or library. The CLI dependency closure has 247 packages and no Qt; the binary needs only `libc`, `libm`, `libgcc_s` and the dynamic loader.
- It writes a deterministic `tar.gz`, `build-manifest.json` and `SHA256SUMS` under `dist/release/` and installs nothing.
- `[profile.release]` sets codegen-units 1, no incremental build and stripped symbols.
- `packaging/arch/PKGBUILD` builds and tests from git with `--frozen` and packages the binary, licence, examples and bash/zsh completions.

MSRV: the full workspace suite passes on Rust 1.98.1, the declared `rust-version` (577 tests; `target/msrv` records rustc 1.98.1), and on 1.99.0 (577 tests).

UX:
- Every command and argument has help text (`release_ux.rs` walks the whole help tree).
- Syntax errors report `usage_kind` and, for a defined argument, its name, without echoing typed values.
- Optional-dependency, capability and limit errors carry a `next` step (`crates/linguist-cli/src/remedy.rs`).
- SIGINT exits 130 and SIGTERM 143 with `INTERRUPTED`. The editor ignores SIGINT while it runs.
- Commands that write state refuse with `STORAGE_FREE_SPACE` when the write would cross `storage.free_space_reserve_mb`.
- `doctor` reports the recorded gate statuses.
- [Command examples for 0.1.0](../examples/commands-v0.1.0.md) are checked against the binary.
- The README describes what 0.1.0 does and does not do.

Tests named by the package:
- **Release gates:** `scripts/release-check.py` writes one GateEvidence record per gate. `release_evidence.rs` checks every record against the contract and against `release-gates.json`.
- **120 semantic fixtures:** `semantic_corpus.rs` and `scripts/generate-semantic-corpus.py`. There are 30 fixtures per workflow, 15 Japanese and 15 English each. They cover Vietnamese explanations, kana/kanji, homographs, mixed models, mixed images, multi-pattern sources, no dictionary match, shared media, task leakage and adversarial text. The run shows zero source loss, no unsupported generated claim or task leakage in ready content, no live markup, and recoverable provenance for every staged value.
- **Model benchmark:** `scripts/model-benchmark.py` with gemma4:12b: 55 of 56 fixtures attempted inference (VA-JA-09 was refused first with `GENERATION_ACCEPTED_ANSWER_REQUIRED`). 52 replies passed the schema and field validation, a compliance of 94.55%, below the 95% target. The other three grammar replies (GA-JA-04, GA-JA-09, GA-EN-08) ended with `OLLAMA_COMPLETION_INCOMPLETE`, meaning `done_reason=length`. Median latency was 9.8 s and the maximum 98 s, with the model using 8.4 GB of VRAM.
- **Final purpose presets:** `crates/linguist-config/tests/presets.rs`.
- **Fresh local config, help and offline use; pipes, JSONL, Unicode, SSH and no terminal; interruption exits; conservative large batches and free space:** `release_ux.rs`. Operations that had no command test (OP-07, OP-15, OP-16, OP-20) are covered by `release_coverage.rs`.

Defects found and fixed by these checks:
- Default dictionary lookups always failed with `CAPABILITY_UNAVAILABLE: PROVIDER_READ_Policy`, because the provider cache path was expanded without the environment.
- Anki 25.09's `Collection.set_deck` clears FSRS memory state (stability, difficulty, desired retention, decay). Companion effects now move cards with `update_card`; a move across presets is refused (`BRIDGE_FSRS_PRESET_CHANGE`). `verify-native-apply.py` covers both.
- Local inference was cut off by `network.request_timeout_seconds` (30 s); it now uses the `llm.timeout_seconds` budget.
- gemma4 spent the output budget on thinking (`done_reason=length`); requests now send `think: false`.
- The decoding schema allowed fields that validation then rejected; it is now narrowed per request to the allowed fields and example count.

## Known limits — revisit after all packages

Release gates and claims:
- **EV-14 blocked** (`CLI_NATIVE_TRANSPORT_UNAVAILABLE`). The shipped CLI cannot apply, restore, roll back, reconcile, create checkpoints or install models: each `--apply` form exits 3. There is no full CLI release claim and no claim that a revamp of a real collection is safe.
- **EV-02 blocked** (`EV02_NONDEFAULT_CONSUMER_TESTS_INCOMPLETE`). Setting coverage is structural (all 156 entries have a consumer or a reported unavailable feature) plus targeted nondefault tests, not one behaviour test per setting.
- **EV-03 blocked** (`NATIVE_COMPANION_NOT_REGISTERED`) and **EV-04 blocked** (`NATIVE_SESSION_REBIND_UNTESTED`). The companion registers no `lab*` mutation actions; there is no live session, epoch, profile or rebind fixture.
- **EV-07 blocked** (`NATIVE_BOUNDARY_FAULT_INJECTION_MISSING`). UUID dedupe, delayed duplicates, removed markers and crash or disk-full boundaries are proven only over the fake native port.
- **EV-09 blocked** (`SPLIT_NATIVE_CRASH_RECOVERY_UNTESTED`). The real-Anki split covers two units and a happy-path apply and rollback; partial-group crash recovery is fake-port only.
- **EV-11 blocked** (`OCR_BENCHMARK_LANGUAGE_PACKS_MISSING`). Only Tesseract `eng`/`osd` are installed, so no OCR benchmark ran. The model benchmark:
  - is one run of one model (gemma4:12b) on the 56 authored add fixtures without dictionary data;
  - uses no repair attempt;
  - measures schema compliance only, not language quality;
  - came in below target: 52/55 (94.55%), with three grammar replies hitting the 2048-token output cap;
  - varies between runs despite temperature 0: an earlier run of the same fixtures gave 54/55, with different failing items.

  The benchmark therefore does not establish the ≥95% requirement.
- Passing gates are scoped to the recorded versions (this machine, Anki 25.09.2 build 3d813c83) and to small disposable collections. EV-06 and EV-10 rest on the companion effect functions through the harness port, not an AnkiConnect transport. EV-12 and EV-13 are local tests (fake native port, loopback servers).
- `release-gates.json` and `doctor` show the statuses of the last release-check run. Code changes do not reset them; rerun the check.

Disposable scenarios:
- The harness does two steps the product cannot do:
  - It publishes a revision bound to the disposable collection, because CLI preparation records no binding.
  - It runs apply, restore, split, rollback and checkpoint export through `linguist_application` over `LabPort` (HTTP to `scripts/disposable-anki-lab.py`), not a CLI transport.
- The lab is not the companion. It has no add-on registration, main-thread critical section, persistent ledger, owner fencing across restarts or crash windows; its ledger lives in memory.
- Revamp review is a harness stand-in. CLI revamp drafts stop at `SOURCE_NATIVE_HISTORY_REVIEW`, which has no resolution, so the harness authors the reviewed migration document from the CLI's captured source archive.
- Model manifest digests are registered by the harness:
  - The observed digest of a note type is the digest of the model JSON the CLI capture recorded.
  - `create_note` compares the fixed managed manifest digest separately.
  - A real companion must compute capture-identical digests; that algorithm does not exist yet.
- Each scenario runs on one small collection (an anchor note plus one or two notes) with no media and no concurrent UI edits.
- Note types are only Basic and the managed v2 models. FSRS is on only in the revamp scenarios.
- The scenarios are `#[ignore]`, so `cargo test --workspace` skips them. They need Anki's Python (`LAB_ANKI_PYTHON`, default `/usr/bin/python3.14`) and are pinned to Anki 25.09.2.
- A studied created note is never removed by restore (`RESTORE_CREATED_NOTE_STUDIED`); there is no supported removal path.

FSRS and effects:
- Cards move through `update_card` because Anki 25.09's `set_deck` drops the memory state.
- A move to a deck with another preset is refused (`BRIDGE_FSRS_PRESET_CHANGE`) instead of recomputing the memory state. The Rust side sees it only as a `failed_before_write` reason; there is no dedicated issue code or recovery advice.
- `update_card` bumps mod/usn per card, so a sync sees card changes. The field update and the deck moves are still separate, non-atomic steps.
- Tested: one default preset, the cross-preset refusal, and only Anki 25.09.2.

Local generation:
- `think: false` is fixed in the request, with no setting. Other thinking-capable models and non-thinking models were not tried against it.
- The decoding schema narrows disallowed fields with `"enum": [""]` and limits examples with `maxItems`. It relies on Ollama's grammar support for both keywords, and `validate_output` still runs. The schema digest now differs per request.
- Inference is bounded only by `llm.timeout_seconds` (default 180 s); `network.request_timeout_seconds` still bounds metadata reads.
- Generated facts always need review (`GENERATED_FACT_REVIEW`), and `GENERATION_ENGINE_UNVERIFIED` keeps generated plans not ready.

Semantic corpus:
- It is deterministic: no LLM, OCR or live dictionary. Dictionary fixtures carry canned Jisho/Wiktionary bytes re-read by the real parsers.
- Revamp fixtures stop at the staged draft and are never rendered.
- Adversarial coverage is limited to HTML, script, iframe, event handlers, encoded markup and template braces.
- Expectations are hand-annotated. Four were corrected after the first run to match intended policy: escaped apostrophes in rendered text, and plain-text examples needing schema review.

Build and packaging:
- One target (x86_64-unknown-linux-gnu). There is no signing (checksums only), no cross-compilation and no other OS.
- Reproducibility was shown by two clean builds (`--clean`) on one machine with one toolchain and remapped paths; it was not checked across machines.
- glibc and libgcc are linked dynamically. Symbols are stripped, so release backtraces have no symbol names.
- `packaging/arch/PKGBUILD` was only parsed (`makepkg --printsrcinfo`). It was not built, because it clones from GitHub, and `namcap` was not run.
- The MSRV toolchain was installed by `mise` into `~/.rustup`. The release check uses it when present and skips nothing else.

UX:
- Interruption exits at once, with no cooperative drain or pause request. This is safe only while no native mutation can be in flight.
  - Helper processes run in their own process group and are not killed.
  - A job lease left behind needs `jobs recover`.
  - Only SIGINT and SIGTERM are handled.
- The free-space estimate is coarse: 8× the input file size, or 1 MiB per selected note. A failed measurement refuses the write; path errors are left to the store.
- `next` hints come from a hand-kept table keyed on error codes, with message matching for `CAPABILITY_UNAVAILABLE`.
- Human output is still key/value lines, and there are no man pages.
- Syntax errors deliberately omit typed values, so an invalid value names only its argument.
- The versioned examples are checked for command paths and flags; they are not executed.
- The OP coverage table finds command tests heuristically (command words inside test bodies). Its handler column points at the first dispatch arm, which is not always the full handler.

Evidence:
- Logs are truncated to the last 60,000 characters and redacted by pattern (repository, home, `/tmp/*`).
- The version matrix describes this machine.
- Gate records embed command and output digests; the outputs themselves are only in the redacted logs.
