## Known limits — revisit after all packages

- **Release evidence predates the review.** The release-check evidence (2026-10-05) predates this review's changes: module-doc tags, three tests, documentation and generators. No product behaviour changed, but the gate records cite the earlier commit. Rerun `scripts/release-check.py` after the next code change.
- **The traceability record is hand-curated.** It cites one to three representative proofs per item, not every relevant test. Algorithm locations come from `ALG-*` tags, so an untagged helper module is not listed.
- **Coverage is matched heuristically.** Operation coverage matches command words in test bodies. Invariant and contract statuses are reviewer judgements checked against named tests, not computed from coverage data.
- **Older records are stale.** `status.md` still contains earlier progress paragraphs, for example "WP-02 is in progress" and "WP-03 is in progress" (RI-07). The final review and the consolidated record give the current statuses. The [safety review](../review/safety.md) and [reconciliation](../review/reconciliation.md) keep their historical text; their current state is in the traceability record.
- **Package limits recorded late.** WP-01–WP-05 had no "Known limits" section; WP-16 recorded their limits in the consolidated record only. WP-02 was audited by this review rather than at implementation time.
- **WP-03 is incomplete.** The open items are recorded as RI-02–RI-05. No new safety defect allowing a collection mutation was found; this is not a security certification.
- **Real-Anki scenarios are opt-in.** They are `#[ignore]` and need Anki's Python, so the default `cargo test` does not show their results (RI-08).
- **The model benchmark misses its target.** It is below the 95% target and varies between runs (RI-06).
