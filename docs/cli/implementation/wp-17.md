### Completion audit 2026-10-06

**Companion (`addons/linguist_bridge`).**

- `startup.activate_native` registers the seven actions with AnkiConnect's own `util.api` decorator after the Anki build and the AnkiConnect `__init__.py`/`util.py` bytes match the pinned matrix; registration is additive and verified through `apiReflect` before and after. Controls require a configured API key (`BRIDGE_AUTH_REQUIRED`); the listener itself rejects a request whose key differs. `labCapabilities` declares the seven mutation variants only with a key and a live session.
- Ledger schema 2 (`operations.py`): immutable operation rows and hash-linked events (`queued` → `running` | `failed_before_write` → `verified` | `unknown`), owner tokens with monotonic fence generations and releases, verified receipts and refusal details. A new owner classifies rows of dead workers (`running` → `unknown(worker_crash)`, `queued` → `failed_before_write(worker_lost_before_write)`) and is refused while live work is in flight. A duplicate UUID with the same payload returns the stored state and never dispatches; a different payload is `BRIDGE_OPERATION_REPLAY_CONFLICT`. An empty v1 ledger upgrades in place.
- Every variant has an exact bounded body (`payloads.py`) and an approval kind: plans authorize forward effects, `lab-restore-decision-v1` digests authorize reverse effects, `checkpoint` and `model-install` digests their own operations.
- `native.py`: `labMutate` checks the session epoch, lineage and current owner fence, queues and returns. A worker takes the collection executor slot (Anki serializes collection operations through one worker) and runs one main-thread critical callback: owner and session are checked again, the read-only preflight runs, `running` is recorded, the native calls run, and an actual read-back closes the row as `verified` with a receipt. Effects are split into read-only `preflight_*` and writing `perform_*` (`effects.py`) so a refusal is provably before any write.
- Native checkpoint export runs in the collection worker like Anki's exporter, announces the temporary close through Anki's hooks, reopens, keeps the session epoch only when profile, path, file identity and collection handle are unchanged, and reports path, size and SHA-256. Model install creates the managed model and verifies its canonical digest.
- `inspection.py` note evidence is served as `labInspect` kind `note_evidence` (raw notetype payload removed).

**Canonical model manifest (RI-05).** `linguist_core::model::ManifestProjection` (name, fields in order, templates by ordinal, CSS; version excluded) is the one digest. Read capture takes ordinals from `findModelsByName`, cross-checks them with the field, template and styling reads and archives the projection; `source.model_manifest`, `create_note`, `install_model` and the companion (`manifest.py`) all use it. A shared vector pins the Rust and Python encodings.

**Transport.** `linguist_anki::Client::native_verified` is the write gate: loopback endpoint, `anki.api_key_env` set, a companion in `VERIFIED_COMPANIONS` (0.1.0 on Anki 25.09.2 with the pinned AnkiConnect digest), all seven variants declared and a live session. `NativePort` implements `ApplyPort`, `CheckpointExporter` and `ModelPort`: accepted mutations are polled to a terminal state; a deadline, a missing ledger row or an ambiguous transport error is unknown; a `BRIDGE_*` refusal of the request itself is a rejection; media is staged create-new by digest in the companion's private staging directory; a checkpoint is copied create-new only when size and SHA-256 match the native receipt. Every effect uses one `{schema_version, variant, body}` wire envelope.

**CLI.** `apply` (items and `--split-group`), `snapshots restore` (live preview with a decision template, `--decision --apply`), `jobs rollback` (`--accept-schema-change`, `--delete-unstudied-created`), `recover reconcile` (`--rebind`), `backup create` and `models install` run their journaled orchestration under the collection-writer lease (600 s, renewed) after a verified full-collection checkpoint through native export, with group IDs shared between checkpoint and writes. `doctor --bridge` reports the write gate. `plans bind` (RI-03) publishes a child revision carrying the verified binding before approval. `plans resolve-history` (RI-04) records a typed `native_history` decision: companion evidence must equal the archived source; every card's ID, ordinal, deck, repetitions, review count and review-row digest is recorded and every card's ordinal must be mapped; the decision adds the task map and stays valid only while the evidence, model digest and map still describe the document. Only `LAB_SECTION__KEY` names are setting overrides (RI-01). `plans edit` may fill an empty `SenseKey`.

**Real-Anki evidence.** `scripts/disposable-anki-desktop.py` creates a new base folder and profile, installs AnkiConnect (pinned bytes) and the companion `.ankiaddon` through `AddonManager.install`, and runs `anki -b BASE` offscreen with `TMPDIR` inside the disposable folder (Anki's single-instance socket never reaches a running user Anki) on a port other than 8765. `desktop_scenarios.rs` (8 scenarios, about 7 minutes) uses CLI commands for every product step; the test only creates decks and source notes, studies cards and observes:

### Known limits — revisit after all packages

- **Compatibility.** Writes are verified only for companion 0.1.0 on Anki 25.09.2 (build `3d813c83`) with the pinned AnkiConnect 2055492159 bytes. Any other Anki or AnkiConnect build is read-only; the matrix is static in both the companion and the CLI.
- **Transport.** Writes require a loopback endpoint and an AnkiConnect API key; the key travels in plain HTTP on loopback. Remote writes are not supported.
- **Concurrency.** The companion accepts one in-flight operation at a time (`BRIDGE_OPERATION_PENDING`); there are no parallel writes. A new `labBegin` replaces the owner when nothing is in flight; protection against a second CLI relies on the local collection-writer lease, so two CLIs with different state directories fence each other (stale requests are refused) rather than queue.
- **Ledger resolution.** A companion row closed as `unknown` stays `unknown` in the companion ledger after the CLI adopts or rejects it from read-back; the CLI journal is the record of the resolution. Unknown rows do not block other operations.
- **Session identity.** Session change is exercised through companion restarts, a hook-driven close/reopen (the path full sync and import use), a profile switch and a lost sidecar. A real `.colpkg` import, an AnkiWeb full sync and same-file replacement by another process are not exercised. The epoch survives only the companion's own checkpoint export, by file identity and handle; a full sync during an export is not tested.
- **Fault injection.** ENOSPC is injected at the ledger `running` boundary (`LINGUIST_BRIDGE_FAULT_FILE`), not a full filesystem; ENOSPC inside a native effect or a collection write is not exercised. Crashes are process exits after the effect; power loss and fsync ordering are not tested. The fault hook ships in the add-on and is inert unless the environment variable names a file.
- **Checkpoints.** Native export writes whole-collection packages only (`backup create --scope affected` with `--apply` is refused). The collection is closed during export, so other AnkiConnect reads fail meanwhile. Very large collections can exceed `backup.verify_timeout_seconds` and end unknown. The CLI deletes the companion's export after its verified copy; staging files for media are not cleaned up.
- **Media.** Media-bearing apply and restore run through the effect probes (`verify-native-apply.py`, `verify-native-restore.py`) and fake-port tests, not through a desktop scenario.
- **Lenient numbers.** `findModelsByName` and note evidence are parsed with 64-bit integers and floats; only names, ordinals, templates, CSS, IDs within the safe range and integer/string evidence fields are used.
- **Evidence bounds.** `resolve-history` uses the bounded inspection (16 cards, 10 000 review rows, 1 MiB media, standard note types); larger notes fail closed. FSRS desired retention and decay are reported but not part of the compared scheduler projection (stability and difficulty are).
- **Review content.** `plans edit` can fill an empty `SenseKey` but cannot set grammar `UseKey`, prompts or examples; a grammar revamp from a sparse source needs `plans split-grammar` (authored units) to become ready.
- **Rollback.** `jobs rollback --apply` builds default decisions and refuses any group with conflicts or blockers; field and deck decisions need `snapshots restore --decision`. A restore journal whose session changed cannot be rebound (`RESTORE_SESSION_CHANGED`).
- **Apply jobs.** `jobs run`/`jobs resume` for simulate and apply jobs still return `CAPABILITY_UNAVAILABLE`; the job executor is not wired to `NativePort`.
- **Models.** `models install` creates the two fixed managed models only; managed model upgrades and other note types are not supported.
- **Evidence environment.** The desktop scenarios need Anki's Python, `/usr/bin/anki`, Linux and the AnkiConnect package (`LAB_ANKICONNECT_ZIP`); they are `#[ignore]` in `cargo test` and run by `scripts/release-check.py`. No CI runs them (RI-08).
- **Open gates and issues unchanged by this package.** EV-02 (nondefault consumer tests), EV-11 (model benchmark below target, OCR packs) and review issue RI-06 remain as recorded in the release evidence.
