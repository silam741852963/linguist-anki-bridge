## WP-22 — grammar add and revamp, end to end on the user's data

Status: planned 2026-10-09. Run in its own session. Independent of WP-20; the batch step depends on WP-21.

### Goal

Prove two flows on the user's real Anki, including the six blue-flagged grammar notes:

- `grammar add` (a new pattern from scratch);
- `grammar revamp` (the user's existing grammar notes into the managed model).

Redesign the grammar card the way vocabulary was redesigned in WP-19.

### Where things stand

- Model `Linguist Grammar v2` (15 fields: Pattern, Meaning, Formation, Usage, Examples, ExercisePrompt, ExerciseAnswer, Audio, PersonalNotes, Source, Language, EnableApplication, UseKey, RecognitionPrompt, ExplanationLanguage). It still has the language, provenance and text-cue fields the user removed from vocabulary in WP-19. Its templates and CSS are the old plain `resources/templates/grammar-*.html` + `style.css`.
- Generation uses `builtin:grammar-v2` (`resources/prompts/grammar-v2.txt`, `GrammarSupplement`: meaning, formation, usage, examples, recognition_prompt, exercise_prompt, exercise_answer). The WP-19 input trimming and the `content_rejected` decision already apply.
- Desktop scenarios exist (disposable Anki): `grammar_add_apply_study_restore_keeps_history`, `grammar_revamp_multi_unit_split_apply_study_rollback`, `grammar_split_crash_resume`. Multi-pattern sources go through `plans split-grammar`.
- User data:
  - deck **夕暮れの詞** has 544 notes of type `Cơ bản` (Basic, Vietnamese UI);
  - Front and back hold the same screenshot image(s), e.g. `<img src="2020-07-04 (18).png">`, sometimes 3–4 images per note;
  - the images are Minna no Nihongo grammar pages, Vietnamese edition: a numbered pattern box (e.g. `Động từ thể ない ないで ください (xin) đừng ~`), a Vietnamese explanation, numbered example sentences with furigana and Vietnamese translations, and `[Chú ý]` notes contrasting similar patterns (e.g. ために vs ように);
  - six of these notes carry a blue flag (`flag:4`).
- **OCR is the blocker.** Tesseract has only `eng` and `osd` (`tesseract --list-langs`). The `jpn`, `jpn_vert` and `vie` packs are missing, which also blocks EV-11. The alternative is `ocr.engine=ollama` with `llm.vision_model=llama3.2-vision:latest` (installed; quality unproven on furigana).

### Decisions to ask the user at the start

1. **OCR engine.** The user installs Tesseract packs (`sudo pacman -S tesseract-data-jpn tesseract-data-vie` — do not run it yourself), or use the Ollama vision model. Recommend Tesseract first, with a side-by-side test against vision on two pages.
2. **Explanation language for grammar.** The sources are Vietnamese. The user chose English for vocabulary. Options:
   - (a) English: the LLM writes English and the Vietnamese source stays archived;
   - (b) Vietnamese: keep the book's Vietnamese meaning and explanation;
   - (c) both: English explanation plus the Vietnamese meaning line.
   - Recommend asking with one sample card rendered each way.
3. **Card design** (propose and render a sample before coding everything). Grammar v3 by analogy with vocabulary v3:
   - fields Pattern, Meaning, Formation, UsageExamples (usage + nuance versus similar patterns + examples with the pattern highlighted), Exercise (prompt + answer), Audio, EnableApplication;
   - languages, JLPT level and lesson number as `lab::` tags;
   - no PersonalNotes, Source, Language, ExplanationLanguage, UseKey or RecognitionPrompt fields;
   - the Recognition front shows the Pattern and one example sentence with the pattern highlighted (fields, not a text cue);
   - Application keeps a text exercise, since it is inherently a cue.
   - `[Chú ý]` contrasts map to Nuance.
   - Confirm with the user before implementing.
4. **One note, several patterns.** Some notes hold several pages or patterns. Recommend `plans split-grammar` with the first pattern keeping the card history, as the existing split flow does.

### Steps

1. **Prerequisites.**
   - Anki is up with companion 0.3.0.
   - Ollama is certified; re-run `doctor --ollama --certify` if its version changed.
   - The OCR decision is settled; run `doctor --local` to confirm the engine and languages.
2. **Survey.**
   - Look at a sample of note images, including all six blue-flagged ones: `findNotes deck:夕暮れの詞 flag:4` gives 1595352323043, 1599308310007, 1599578063504 and others; re-run the query.
   - Record pattern count per note, page layout, and lesson numbers if visible.
3. **OCR quality gate.**
   - On five pages, compare the OCR text with the image: pattern, formation, examples (furigana must not be merged into the base text), and translations.
   - Tune `ocr.page_segmentation_mode`, `ocr.preprocess` and `ocr.languages`, or switch engine.
   - Use OCR review (`OCR_REVIEW_CODES`) for low-confidence regions.
   - Do not continue until patterns and examples read correctly.
4. **Grammar v3 model** (after decision 3):
   - add `model::grammar()` → v3 (or a new `grammar_v3`, keeping v2 accepted in the companion);
   - templates and CSS reuse the vocabulary v3 visual system (`vocabulary-v3.css` classes);
   - render: structured meaning, highlighted pattern in examples, a nuance section;
   - tags;
   - validation (Recognition needs Pattern and an example; Application needs exercise prompt and answer);
   - a `grammar-v3` prompt and supplement (usage, nuance against similar patterns, examples, exercise);
   - add the field set to the companion payload `FIELDS`, bump the companion version and `VERIFIED_COMPANIONS`, and reinstall into the user's Anki (normal window close, unzip over `~/.local/share/Anki2/addons21/linguist_bridge`, restart);
   - update the tests and the semantic corpus (`scripts/generate-semantic-corpus.py`);
   - update `verify-template-cards.py` and the desktop scenarios.
5. **Grammar add (new pattern).**
   - `grammar add --document` with an authored pattern the user does not have; ask, or pick one from the next lesson.
   - Then: generation (certified), review, `models install japanese_grammar --apply` (v3), bind, approve and apply.
   - Render the card and look at it.
6. **Grammar revamp, one at a time** (start with one single-pattern blue note, then one multi-pattern note):
   - `grammar revamp --note-id N` with the field mapping for `Cơ bản` (`Mặt trước` front, `Mặt sau` back; both are images, so OCR supplies the content);
   - OCR review;
   - segmentation review and `plans split-grammar` when there are several patterns;
   - certified generation; read every generated fact and reject wrong ones (`content_rejected`);
   - apply with `--accept-schema-change`;
   - check card IDs, reps, intervals and due dates are unchanged and every media reference exists;
   - keep the original screenshots archived; do not render them unless the user asks.
7. **The six blue-flagged grammar notes**, through the batch path from WP-21 if it is done, else one by one.
8. **Hand-off.**
   - Publish a review sheet (an artifact) covering both flows: the new note, the revamped notes, and what was uncertain (OCR fixes, rejected facts).
   - Remind the user to choose **Upload** on the next full sync.
   - Add a completion audit and exhaustive **Known limits** here.
   - Rerun `scripts/release-check.py --msrv --release-build --benchmark`; EV-11 may now pass if the Tesseract packs were installed.
   - Commit and push each milestone.

### Done when

- One new grammar note and the six blue-flagged grammar notes (plus at least one multi-pattern split) are on the managed grammar model in the user's Anki, with history unchanged and media present.
- The grammar desktop scenarios and verify scripts pass with the new model.
- The user has reviewed the cards.
